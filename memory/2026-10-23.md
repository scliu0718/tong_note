## WorkLog macOS 富文本编辑器（2026-10-23 17:30）

### 本次改动

把 Markdown 编辑器改为真富文本，新增 `WorkLogRichText` 模块（macOS AppKit 层）。

**架构分层**

- `WorkLogCore`（纯 Foundation，跨平台可复用）：`RichTextDocument` 模型、`RichTextHTMLCodec` 受控 HTML 编解码、`MarkdownConverter` 旧格式兼容、`AttachmentStore` 附件仓库。
- `WorkLogRichText`（AppKit）：`RichTextBridge`（NSAttributedString ↔ 文档双向转换）、`RichTextEditorController`（编辑命令）、`RichTextEditor`（NSViewRepresentable）、`RichTextNSTextView`（粘贴图片）。

**存储格式决策**

- 正文存带版本标记的受控 HTML；图片只存相对路径 `attachments/<note-uuid>/<image-uuid>.<ext>`，绝不用 Cocoa HTML Writer 的 `file:///Attachment.tiff`。
- `Note.contentFormat` 新字段（markdown/richText），自定义 `init(from:)` 保证旧 notes.json 可解码；正文+格式用 `updateContent(_:body:format:)` 原子写入，避免中间态。
- 旧 Markdown 笔记只兼容渲染，用户实际编辑后才升级为 HTML。

**功能**：加粗/斜体/下划线/删除线、字号（11-40）、文字颜色（9色预设+原生 ColorPicker）、分段（正文/H1-3/引用/代码）、无序/有序列表（真实 NSTextList 序号）、链接、本地图片插入、**粘贴图片自动成图**。

### 踩过的坑（重要）

1. `NSColor(calibratedRed:)` 转 sRGB 会偏移，十六进制无法往返 → 必须用 `NSColor(srgbRed:...)`。
2. `NSFontDescriptor.SymbolicTraits` 在 Swift 里是 `.bold`/`.italic`，不是 `.boldFontMask`；`NSFontManager.convert` 要用 `NSFontTraitMask`。
3. `NSParagraphStyle` 属性名是 `paragraphSpacing`，不是 `paragraphSpacingAfter`。
4. `NSTextList` 的 options 参数是 Int（传 0），不是 `NSTextList.Options()`。
5. HTML 属性解析器状态机有缺陷 → 改用正则逐个匹配；重复 `style` 要合并而非覆盖。
6. `NSColorPanel` 的 delegate 协议在 Swift 不可用 → 改用 macOS 14 原生 `ColorPicker`。
7. `NSViewRepresentable` 里 `updateNSView` 必须重新绑定 `onPasteImage` 回调，否则笔记切换后粘贴会写进旧笔记的附件目录。

### 补充：粘贴路径文本自动成图（2026-10-23 18:00）

用户反馈粘贴微信图片**路径文本**（不是图片文件）时显示成文字。根因：剪贴板里只有字符串，旧的 paste 只识别「文件URL」和「位图数据」两种。

**改动**
- 新增 `WorkLogCore/ImagePathScanner.swift`：纯 Foundation 的本地图片路径识别（跨平台共用）。
  - 从扩展名往前回溯路径边界；按斜杠边界逐级尝试候选；只认文件确实存在的。
  - 支持含空格的路径（`/Users/me/我的 图片/a.png`）。
  - 路径混在文字中时按段切分，路径段变图片、文字段保留。
- `RichTextNSTextView.paste` 增加第三种来源：路径文本 → `onPasteText` 回调。
- `RichTextEditorController.insertTextWithImagePaths(_:)`：分段构建 attributed string，图片位置放 `NSTextAttachment`。
- `RichTextEditor.installPasteHandler` 同时绑定 `onPasteImage` 与 `onPasteText`。

**又发现两个真实缺陷**
1. **图片显示尺寸退化成 160×90 占位图**：早期 src 污染 → 读图失败 → 退化成占位图 → 占位尺寸又写回正文，自我循环。
   修复：`RichTextBridge.fittedBounds` 改为以附件文件**真实尺寸**为准，不采信正文里的声明尺寸。
2. **打开笔记会重写正文**：`encode` 给每块加尾随 `\n`，导致「载入→回写」不一致。
   修复：块之间用 `\n` 分隔但**最后一块不加尾随换行**，保证编码幂等。

**踩坑**
- `NSTextAttachment` 是系统类，不能加自定义属性 → 用 `(NSTextAttachment, String)` 元组把相对路径带回调用方。
- `NSImage.size` 返回**点尺寸**；非 Retina 下与像素一致，但断言时别拿它和 sips 的 pixelWidth 混比。
- 真实数据渲染测试里不能用 `attributed.attribute(.attachment, at: 0)` 固定取第一个附件 —— 多图时必然错配，要按 imagePath 逐个匹配。

**数据修复**
- `scripts/fix_path_text_images.py`：路径文本转内联图片 + 按附件真实尺寸修正 width/height。
- 验证：69 项 XCTest 全绿；真实数据 5 张图片全部加载正确、尺寸一致；应用启动前后 notes.json 哈希不变（打开笔记不再改写正文）。
