三、真实缺陷与修复

#现象根因修复
缺陷 1 A06 配额查询 errno=2 xpan/nas?method=quota 被百度拒绝 改用 api/quota?checkfree=1&checkexpire=1。注：Mac 端有同样潜在问题，只是从未走到该分支
缺陷 2 B 组整体崩「character set provided in ContentType is invalid」 百度响应 Content-Type 带的字符集 .NET 无法解析，ReadAsStringAsync 直接抛异常 统一改为按字节读取再 UTF-8 解码（ReadTextAsync），全链路替换
缺陷 3 下载报 BaiduPanNotFoundException / errno 20020 第三方应用沙箱目录不支持 method=download 取直链 降级：列举父目录取 fs_id → filemetas?dlink=1 → 带 token 与 UA 下载；模型补 FsId
缺陷 4 GUI 首轮同步永久卡在 Syncing（240s+） ShellView 在后台线程的事件订阅里直接改 UI 控件，造成同步轮死锁 加 OnUi(Action)（Dispatcher.UIThread 判定 / Post）包裹全部会话订阅；SyncEngine 落 sync-status.json 快照、隔离订阅者异常、瞬态失败自动重入重试；请求超时 90s。修复后 G05 由卡死变为 14.5s 完成
缺陷 5 直链偶发 HTTP 404 + errno 31066，抛通用异常导致整轮回归中断 下载阶段 404 未映射为 NotFound；而 SyncEngine 有 5 处依赖 NotFound 把「云端文件不存在」当正常路径 识别 404/31066 后先重取一次直链重试（避免把实际存在的笔记误判成缺失、走新增或覆盖分支），两次仍 404 才抛 BaiduPanNotFoundException
测试假设误判（非产品缺陷，已按 Mac 真实行为纠正断言）： Mac 的 encodeIfPresent 同样省略 null 可选字段（deletedAt）；同步徽标实际为 _sidebarSync / UpdateSyncLabels；编辑器桥接是 setContent 而非 setHTML；工具条命令在 C# 侧而非 HTML 内；头像仅在用户主动选择时上传；F06 应等 Status.Kind 而非 LastSyncDate。
