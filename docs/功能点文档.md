## 2. A · 账号与登录

| # | 功能点 | 入口 | 行为 | 边界 |
|---|---|---|---|---|
| A-01 | 登录态路由 | App 启动 | `auth.isSignedIn == true` → `MainView()`，否则 `LoginView()`；`Group` 内二选一，无共存、无过渡动画 | 由 `BaiduPanAuthService.state` 派生，全局仅两个 `@StateObject`（auth / sync） |
| A-02 | 系统 Web 会话登录 | 登录页主按钮「使用百度网盘账号登录」 | `ASWebAuthenticationSession` 打开 `authorizeURL(state:, display: "popup")` → 取 `code` → `exchangeCode` → `finishSignIn()` | 发送了 `state` 但**回调未校验**，仅依赖系统 callback scheme 隔离 |
| A-03 | 浏览器扫码登录 | 登录页次按钮「浏览器扫码登录」 | `signInViaBrowser()` 生成 `nonce` 存 `pendingBrowserState`，`NSWorkspace.open` 打开 `display=page` 授权页 → 回调经 `onOpenURL` → `handleCallback` | 只有当 `pendingBrowserState != nil` 才校验 state；无 `code` 时静默 return |
| A-04 | OAuth 回调接收 | `tongnote://oauth/callback` | `WorkLogApp.onOpenURL` 无过滤地转给 `auth.handleCallback(url)`；`Info.plist` 注册 scheme `tongnote`（`CFBundleURLName = com.tong.log.app.oauth`） | `onOpenURL` 不判断 host/path |
| A-05 | 授权参数 | — | `response_type=code`、`client_id=appKey`、`redirect_uri=tongnote://oauth/callback`、`scope=basic,netdisk`、`display`、`state` | 端点 `https://openapi.baidu.com/oauth/2.0/authorize` |
| A-06 | token 交换 / 刷新 | 内部 | `exchangeCode(code)` / `refresh(token)` → `BaiduPanTokenStore.save` 落盘 | token 提前 5 分钟视为过期；刷新沿用旧 `refresh_token`（字段非 optional，服务端不返回时会先解码失败） |
| A-07 | token 存储 | — | `~/Library/Application Support/tonote/baidupan-token.json`，`JSONEncoder` + `.atomic` + 代码强制 `chmod 0600`；启动时 `cleanupLegacyKeychain()` 删除旧 Keychain 条目 | 弃用 Keychain 的原因：临时自签名每次变化会反复弹钥匙串验证 |
| A-08 | 凭证配置 | 构建期 | `baidupan.secret.json`（`appKey`/`appSecret`/`appID` 三字段）由 `build_app.sh` 复制进 `Contents/Resources/`；`BaiduPanConfig.loadSecret()` 优先 bundle、其次进程工作目录 | `appID` 定义后全仓无使用点，但结构体强制要求该字段；缺 secret 时打包只警告不失败，登录必然不可用 |
| A-09 | 登录页内容 | `LoginView.swift` | 左品牌区（绿色渐变 + 主标语 + 三条卖点 + 页脚）、右登录区（标题/主按钮/错误 banner/「或」/扫码按钮/扫码说明/授权说明） | 页脚写「worklog 目录」，与实际 `/apps/tong_log` 不一致；两条失败文案一个指向 `BaiduPanConfig.swift`、一个指向 `baidupan.secret.json` |
| A-10 | 账号信息加载 | `SyncView.task` / 登录后 | `loadAccount()` 拉 `userInfo` / `quota` | 失败静默忽略，登录态仍有效 |
| A-11 | 退出登录 | 设置面板「退出」按钮 | `dismiss()` + `auth.signOut()`：`client.logout()` 清 token、`state = .signedOut`、清 userInfo/quota | **不清设备编号、不清本地笔记数据** |
| A-12 | 重新授权 | 设置面板「重新授权」 | 直接走浏览器扫码路径 `signInViaBrowser()`，不经 `ASWebAuthenticationSession` | — |
| A-13 | 登录中状态 | 两个按钮共享 | `isAuthorizing` 时两个按钮均 `disabled` 并显示 `ProgressView` | 未做流程互斥，扫码流程中再点主按钮会覆盖 `pendingBrowserState` |

> **不存在的功能**：手动粘贴授权码输入框、设备码登录、账号密码登录、第三方账号（Apple/微信）登录、多账号切换。

## 3. S · 云同步

### 3.1 三种「同步」概念辨析（易混淆，务必区分）

| 名称 | 定义 | 实际行为 |
|---|---|---|
| `SyncEngine.quickSync(store:todos:)` | `SyncEngine.swift:57` | **全量一轮**的薄封装，名字里的 quick 不表示单篇或快速路径 |
| `SyncEngine.syncSingleNote(..., noteID:)` | `SyncEngine.swift:62` | 只处理指定 UUID 的笔记，**跳过笔记本与任务**，`lastMessage` 固定「已同步本篇」 |
| 「快同步」虚拟笔记 | `NoteStore.quickSyncNoteID` | 固定 UUID `E1C2D3A4-B5F6-47C8-9D0E-1F2A3B4C5D6E` 的一篇特殊笔记，是单篇同步的 **UI 载体**；点击列表卡片只是打开这篇笔记，不是发起同步 |

### 3.2 功能点

| # | 功能点 | 入口 | 行为 | 边界 |
|---|---|---|---|---|
| S-01 | 启动同步 | `MainView.task` | App 进入主界面立即跑一轮 `syncRound` | 需已登录 |
| S-02 | 定时同步 | `MainView.task` 循环 | 每 **45 秒**一轮，仅当 `scenePhase == .active` | `while !Task.isCancelled` |
| S-03 | 回到前台同步 | `.onChange(of: scenePhase)` → `.active` | 再跑一轮 | 与 A-15 的 `enforceDeviceSession` 是两条独立链路 |
| S-04 | 防抖同步 | `.tonoteLocalDataChanged` 通知 | `SyncEngine.schedule` 取消旧 Task → 睡 **1.5 秒** → `syncRound`；连续保存只跑最后一轮 | 通知由 `SyncCursorStore.markDirty` 与 `NotebookStore.persist(dirty: true)` 发出；同步回写**不发**该通知，避免回环 |
| S-05 | 手动全量同步 | 列表「一键同步」、设置「立即同步」、任务页「同步」 | `sync.quickSync(...)` | 按钮在 `isSyncing` 时禁用并显示进度 |
| S-06 | 单篇同步 | 「快同步」笔记右上角「同步」按钮 | `sync.syncSingleNote(...)` | 只该篇；成功显示「已同步 HH:mm」，失败显示「失败：…」 |
| S-07 | 任务页自动同步 | 任务任何变更 `mutate {}` | `scheduleAutoSync()`：防抖 **1.2 秒**；未登录不执行；若上一轮仍在跑，每 0.5 秒等待最多 20 次（10 秒） | 与 S-04 是两套独立防抖 |
| S-08 | 按篇云端存储 | 内部 | 每篇笔记 `notes/<UUID>.json`、每条任务 `todos/<UUID>.json`、笔记本 `notebooks.json`、附件 `attachments/<UUID>/`、设备 `devices/<ID>.json`、头像 `avatar.json`、旧格式 `manifest.json` | 根目录 `/apps/tong_log` |
| S-09 | 分片上传 | 内部 | `precreate`（4 MiB 分片 + 每片 MD5 + `rtype=3` 覆盖 + `autoinit=1`）→ `superfile2` 分片上传 → `create`；`return_type == 2` 秒传跳过上传；`User-Agent: pan.baidu.com` | `CC_MD5` deprecated 但百度接口要求，保留 |
| S-10 | 下载 | 内部 | xpan `method=download` 取 `dlink` → 追加 `access_token` → 带 UA 拉取 | 非 JSON 响应带原文报错；JSON 但 `errno != 0` 一律折叠为 `notFound` |
| S-11 | 三方合并 | `SyncRules.afterFetch` | 用 `rev` 判断云端是否变化、`updatedAt` 定冲突胜负、`SyncCursor` 记上次基线；产出 `skip / rememberMtime / useRemote / upload(rev:) / conflict` 五种决策 | **不是简单 last-write-wins**；`sameTime` 容差 1 秒 |
| S-12 | 增量跳过 | `shouldSkipFetch` | `!cursor.dirty` 且 `server_mtime == cursor.serverMtime` 时跳过下载正文 | mtime 粒度变化会导致重复下载或漏拉 |
| S-13 | 冲突副本 | `resolveConflict` | 两边都改 → 输的一方另存标题带「（冲突副本）」的新 UUID 副本并上传；`remoteWins` 平局云端胜 | 反复冲突会产生多份副本 |
| S-14 | 回读校验与重试 | `publish` / `publishTodo` | 上传后回读比对 `rev` 与 `sameTime(updatedAt)`；最多 **3 次**，仍失败抛「连续三次没能写上云端」 | 单篇失败用 `firstError` 收集，遍历完所有 ID 后统一抛出，不中断整轮 |
| S-15 | 附件同步 | 内部 | 正文正则提取 `attachments/<UUID>/<UUID>.<ext>` → 跳过 `cursor.uploadedAttachments` 已传项 → 上传；下载时本地缺失才拉，失败返回 `false` 并置 `serverMtime = nil` 让下轮重试 | 本地文件不存在静默跳过；云端无该图静默跳过 |
| S-16 | 笔记本同步 | 全量轮 | `NotebookMerge.merge`：`names = (本地 ∪ 远端) − removed` 排序、`removed` 取并集；`changed` 才上传 | **单篇同步跳过笔记本**；内置笔记本不进 `notebooks.json` |
| S-17 | 墓碑与彻底删除 | 内部 | `purged = true` 时只上传带墓碑的 JSON、不传附件；成功后若无其他笔记引用则删除云端附件目录 | 不删除远端 note 文件本身 |
| S-18 | 旧格式迁移 | `migrateNotesIfNeeded` / `migrateTodosIfNeeded` | `notes/` 为空且旧 `manifest.json` 有数据时，按 `updatedAt` 合并后拆成按篇文件 | `manifest.json` 此后不再写入 |
| S-19 | 同步状态呈现 | 设置面板 / 快同步笔记 / 列表按钮 | `status = idle / syncing / success(Date) / failed(String)`；`lastMessage`、`lastSyncDate` 写 `UserDefaults["tonote.lastSyncDate"]` | 同步失败**不退出登录**，只留到下一轮重试 |
| S-20 | 并发合并 | `syncRound` | `status.isSyncing` 时置 `needsAnotherRound = true` 并 return；结束后最多补跑一轮 | 仅单个 Bool，多轮并发请求最多补一轮 |

> **同步中不包含的数据**：头像（独立 `AvatarStore` 链路）、设备清单（独立 `DeviceRegistry`），二者不参与 `syncNotes` / `syncTodos` 的合并；但 `syncRound` 开头与每次 `publish` 前都会调 `ensureNotKicked()`。
> **本地文件**：`note-sync.json` / `todo-sync.json`（`SyncCursor` 对照表）只落本机，不上传；换设备或重装后 `baseRev = 0`，靠 `afterFetch` 的 `neverSynced` 分支按 `updatedAt` 兜底。

## 4. D · 设备会话与安全

| # | 功能点 | 入口 | 行为 | 边界 |
|---|---|---|---|---|
| D-01 | 设备身份 | 首次启动 | `DeviceIdentityStore.loadOrCreate` 生成 UUID 设备号写 `device.json`；`updateSession` 只换 sessionId | 设备号生成后不变，**退出登录不删除**；`NSLock` 保护 |
| D-02 | 登录后登记 | `finishSignIn` → `beginLogin()` | 换一个新的 sessionId 并覆盖写自己的 `devices/<本机ID>.json`（`kicked: false`） | 设备登记失败被忽略，仍保持登录 |
| D-03 | 设备列表 | 设置面板「登录设备」卡 +「刷新」 | `listDevices()` 列 `devices/*.json`、逐个下载解码，本机排最前、其余按名称排序 | 串行下载，设备多时请求数线性增长；云端读不到本机时用 `localSnapshot()` 补一行 |
| D-04 | 手动下线设备 | 每行「下线」→ 确认 alert | `kick(deviceId:)` 把**对方**文件 `kicked` 置 true，不改其 sessionId、不写本机文件 | 不能踢自己；已 kicked 则静默 return；设备号需通过 `^[A-Za-z0-9-]{8,80}$` 校验 |
| D-05 | 被踢自我登出 | 打开 App / 回前台 / 每轮同步 / 每次 publish / 头像上传 | `ensureNotKicked` 读本机文件 → `DeviceRecord.decision` → `.kicked` 时发 `.tonoteDeviceKicked` 通知并抛错 → `AppRoot.onReceive` → `signOutFromKick()` → 回登录页 | **离线时无法及时感知**；网络错误（非 kicked）不退出 |
| D-06 | 被踢提示 | 登录页 banner | 「本机已在其他设备被下线，请重新登录」；下次发起登录时清掉 | 本地笔记不清空 |
| D-07 | 设备名 | 内部 | `Host.current().localizedName ?? host.name ?? "Mac"`，去空白 | 含中文/空格也可，仅用于显示与排序 |
| D-08 | 凭证安全 | 构建/运行 | `.gitignore` 忽略 `baidupan.secret.json`、`.build/`、`*.app/`、`.DS_Store`；secret 与 token 文件均 0600 | 笔记数据 `notes.json` 明文存储，与 token 同安全等级；`client_secret` 走 GET query |

> **准确口径**：当前**没有**「新设备登录自动把旧设备挤下线」的自动互踢逻辑。真实语义是「**手动下线设备 + 被标记设备下次校验时自我登出**」，且被下线的设备重新登录即可自行解绑（`decision` 在 sessionId 不同时返回 `.publish`，把 `kicked` 覆盖回 false）。

### 13.1 表格几何常量（当前磁盘实测值）

| 常量 | 值 | 说明 |
|---|---|---|
| `columnLeadingInset` / `columnTrailingInset` | 5.5 | `collapsesBorders` 让相邻两格共用边框，可见竖线落在 11pt chrome 的中点 |
| `verticalChrome` | 7 | TextKit 对上下边框不合并，写成 3.5 会让加行圆比横线低 3.5pt |
| `dotInset` | 12 | 列圆在顶边上方 |
| `tableLeadingMargin` | 16 | 加行圆横坐标锁在正文起点 `bodyTextMinX` |
| `dotHitRadius` | 22 | 蓝色加号半径 10，实际点击常落在圆心偏表格一侧 15–20pt |
| `textContainerInset` | 24×24 | 给外侧灰圆留空间 |
| 灰圆 / 蓝圆 / 引导线 | 共用同一 edge | 与边线重叠，不错开 |

> **TextKit 1 是硬约束**：`NSTextTable` 只在 TextKit 1 里横排并画边框。手动 `init(frame:textContainer:)` 必须显式设 `minSize=(0,0)`、`maxSize=(greatestFiniteMagnitude, greatestFiniteMagnitude)` 且 frame 不能是 `.zero`，否则编辑器无法自动撑高、滚动失效（历史 Bug「支持表格后编辑区不支持滚动了」）。
> 遮罩层 `isFlipped = true`、`hitTest` 恒返回 `nil` 让事件穿透给 `NSTextView`。**不要用 `visibleRect` 给加行圆定位**（初始布局未稳定、坐标空间不一致，会造成「画在左、命中在右」）。

## 21. 边界与已知限制速查（写文档/做产品决策前必读）

1. **置顶不参与排序键**：仅因 `togglePin` 刷新 `updatedAt` 而在「最近更新」下间接置顶；「按创建」「按标题」下不生效。
2. **回收站视图下搜索/笔记本/标签过滤被跳过**，但搜索框仍可见可输入，用户会感觉「输入无反应」。
3. **「快同步」卡片点击只打开笔记**，不发起同步（代码注释与实际不符）。
4. **无本地自动备份文件**，只有 `.atomic` 原子写入防损坏。
5. **本地 Store 无 `@MainActor`/锁/队列**，CRUD 直接改 `@Published` 数组并在调用线程同步写盘；只有设备身份层用 `NSLock`、头像层用 `MainActor.run`。这是「隐含主线程假设」，代码无显式保证。
6. **无深色模式适配**：`Theme` 全为固定浅色 hex，全工程无 `colorScheme` / 动态色 / `preferredColorScheme`。
7. **设计令牌不完整**：无统一圆角/字号/间距令牌，均为字面量；大量界面色值未收进 `Theme`。
8. **同步链路存在有意静默降级**：secret 解码失败 return nil、附件本地缺失 continue、云端无该图 continue、头像拉取失败保持默认、`downloadData` 把所有非 0 errno 折叠成 `notFound`、`uploadBlock` 对非 JSON 200 响应不报错。产品语义上「同步失败」被定义为可重试降级，而非立即阻断。
9. **ASWebAuthenticationSession 路径 state 只发不验**；`handleCallback` 在 `pendingBrowserState == nil` 时跳过校验。
10. **平局方向不一致**：`SyncRules.remoteWins` 平局云端胜，`mergeByUpdatedAt`/`mergeTodos` 平局本地胜（分别发生在冲突与迁移两个阶段）。
11. **旧 Markdown 转换是有损简化**：代码围栏行被丢弃、标题仅到 h3、连续普通行合并为单段、只有 `attachments/` 前缀的 `![](...)` 才转图片。
12. **不存在 `Notebook` / `Tag` / `DeviceSession` 三个独立类型**：分别由字符串常量 + `[String]` + `Notebooks` 枚举 / `Note.tags` / `DeviceRecord` 等承载。
13. **`data-fullwidth` 在 `<table>` 上，不在 `<td>` 上**；`<td>` 上是 `data-align` / `data-bg`。
14. **`NoteStore.setNotes` 注释与实现不符**（声称刷新 `updatedAt`，实现未刷新）；`applySyncedTodo` 无附件清理而 `applySyncedNote` 有。
15. **富文本模型全部不是 `Codable`**，持久化依赖受控 HTML；`Note` / `Todo` 才是 Codable。
16. **登录页宣传「Markdown 笔记 + 附件」**，而当前编辑器主体是富文本 HTML（`NoteContent.format` 支持 `.markdown`/`.richText`，旧笔记首次打开时按 Markdown 渲染，编辑后升级为 `.richText`）。
17. **账号名「老王的工作台」硬编码**，真实账号名只在设置面板显示。
18. **`baidupan.secret.json` 缺 `appID` 字段**会让整个 secret 解码失败，但 UI 只报「尚未配置 AppKey / AppSecret」，有误导。
19. **构建脚本缺 secret 只警告不失败**，产物可打包但登录不可用。
20. 以上内容均为**当前磁盘代码事实**；工作区 9 个文件处于并行开发未提交状态，后续版本可能变化。
