## 1. 设计总览

### 1.1 产品约束（从代码反推）

| 约束 | 落地方式 |
|---|---|
| 数据归用户所有、无自有服务器 | 所有笔记/任务/附件直接写入用户自己的百度网盘 `/apps/tong_log`，App 只做读写 |
| 格式开放、可迁移 | 正文用受控 HTML 字符串（而非私有二进制），笔记/任务用 prettyPrinted JSON，附件用相对路径 |
| 跨端（macOS / Android）一致 | `WorkLogCore` 纯 Foundation，不依赖 AppKit；`ImagePathScanner` 明确注释跨平台共用 |
| 离线可用 | 本地 JSON 原子写入先落盘，云端同步为可重试降级，失败不退出登录、不清本地数据 |
| macOS 原生体验 | SwiftUI 外壳 + AppKit `NSTextView`/TextKit 1 承载富文本与表格 |

### 1.3 三条主干数据流

**A. 笔记编辑（载入 → 回写）**

```
content.body
  → [.richText ? RichTextHTMLCodec.decode : MarkdownConverter.toDocument]
  → RichTextBridge.attributedString(from:attachments:)
  → tv.textStorage.setAttributedString
  → 用户编辑 / 命令层改属性
  → repairIdentity + normalizeListMarkers（isUpdatingProgrammatically + 禁用 undo）
  → RichTextBridge.document(from:) → RichTextHTMLCodec.encode
  → parent.content = NoteContent(body: html, format: .richText)
  → NoteStore.updateContent(_:body:format:) 原子写入 body + format
```

**B. 同步（按篇）**

```
触发（启动 / 45s 定时 / 回前台 / 1.5s 防抖 / 手动）
  → SyncEngine.syncRound（@MainActor）
  → validToken() → DeviceRegistry.ensureNotKicked(accessToken:)
  → listJSON(notes/) 得到 [UUID: server_mtime]
  → 遍历 remoteIDs ∪ localIDs → syncOneNote
      → shouldSkipFetch（可跳过下载）
      → downloadNote → SyncRules.afterFetch → 5 种 SyncStep
      → publish（最多 3 次，回读校验 rev + sameTime(updatedAt)）
      → resolveConflict（另存「（冲突副本）」）
  → syncNotebooks / syncTodos（单篇同步时跳过）
  → status = .success(date) / .failed(msg)
```

**C. 表格命令（两条回写路径）**

| 类别 | 命令 | 回写方式 |
|---|---|---|
| 就地改属性 | `setCellAlignment` / `setTableCellBackground` / `setTableFullWidth` | 只改 `NSTextStorage` / `NSTextTableBlock` 属性 → `commitChanges()` → `persist`。**不重建整表**，保住表格 ID、列宽、undo 栈、光标与正在输入的文字 |
| rewrite 整表 | `insertTable` / 增删行列 / `deleteTable` / 末格 Tab 新增行 | `RichTextTableEditor.rewrite` → 全表 `attributedString(for:)` → `shouldChangeText` + `replaceCharacters` → `didChangeText()` → `textDidChange` → `persist` |

## 3. 技术选型与关键决策

| # | 决策 | 理由（代码内注释/可推断动机） | 代价 / 约束 |
|---|---|---|---|
| D-01 | SwiftUI 外壳 + AppKit `NSTextView` 承载编辑器 | 需要 `NSTextTable` 画表格边框、精细控制粘贴/选区/光标 | `NSViewRepresentable` 嵌 SwiftUI 后编辑菜单 `paste:` action 转发不可靠，必须三保险拦截 |
| D-02 | **强制 TextKit 1** | `NSTextTable` 只在 TextKit 1 里横排并画边框 | 手动 `init(frame:textContainer:)` 必须显式设 `minSize=(0,0)`、`maxSize=(greatestFiniteMagnitude,...)` 且 frame 非 `.zero`，否则编辑器不撑高、滚动失效 |
| D-03 | 正文持久化用**受控 HTML 字符串**，不是 `NSAttributedString` 归档 | 跨端解析一致、正文不出现 `file:///Attachment.tiff`、图片只存相对路径 | 富文本模型全部**不是 Codable**，需自写编解码器与极简 HTML 解析器 |
| D-04 | `NoteContent { body, format }` 两个字段**一起原子写入** | 避免「HTML 正文 + markdown 格式」中间态 | `NoteStore.updateContent(_:body:format:)` 必须同时写两字段 |
| D-05 | 图片落盘后只存 `attachments/<noteUUID>/<imageUUID>.<ext>` | macOS / Android 同步后仍指向同一份附件 | 必须严格禁止系统默认粘贴产生的临时引用 |
| D-06 | **按篇同步**（每篇一个云端 JSON） | 增量、可单篇同步、冲突粒度细 | 需 `SyncCursor` 对照表；旧 `manifest.json` 需一次性迁移 |
| D-07 | 三方合并（`rev` + `updatedAt` + `cursor`），不是简单 LWW | 区分「云端变了」「本地变了」「两边都变」 | 决策分支多；平局方向在冲突与迁移两阶段不一致（§15） |
| D-08 | token 存 0600 文件而非 Keychain | 临时自签名 `codesign -s -` 每次构建签名变化，Keychain 视为陌生程序反复弹验证 | 与 `notes.json` 明文同等安全等级；启动时清理旧 Keychain 条目 |
| D-09 | 凭证放 `baidupan.secret.json`（.gitignore + 0600），构建时复制进 bundle | 不进 git 历史 | 缺 secret 打包只警告不失败；`Secret` 三字段全 required |
| D-10 | 单元格属性**就地改**、结构编辑才 rewrite | 保住表格 ID、列宽、undo 栈、光标与正在输入的文字 | 需要 `isFixedWidth` 从 `contentWidthValueType` 兜底推断宽度模式 |
| D-11 | 表格边沿遮罩层 `hitTest` 恒 `nil` | 事件穿透给 `NSTextView`，不影响选字与光标 | 命中判定需自己实现，且不能用 `visibleRect` 定位加行圆 |
| D-12 | 多个 `.alert` 合并为单一 `activeDialog` 状态 | 多个 `.alert` 串在同一 SwiftUI 视图上只有部分生效（失败提示弹不出来） | `SidebarView` 与 `EditorView` 各有一套独立状态机 |
| D-13 | 同步失败视为**可重试降级**，不退出登录 | 「失败只留到下一轮」，离线编辑仍可用 | 存在多处有意静默忽略（§15.3） |
| D-14 | `listMarker` 是视图层前缀，不写进 HTML | 编号/圆点由渲染层生成，避免污染文档 | 必须防御 `typingAttributes` 继承、末尾 `\t` 属性污染、标记范围计算 |
| D-15 | `allowsNonContiguousLayout = true` | 大表格几百个格子，默认会先把整表排完再显示，切笔记时主线程卡几秒 | 需要 `rebuildTableRowSpans` 每主队列回合补一整行 |
| D-16 | 选中文字浮动窗口保留代码但 `isEnabled = false` | 按需求临时关闭，可一键恢复 | `SelectionFormatBar` 当前不可达 |

## 4. 应用启动与状态管理

### 4.1 入口

```swift
@main
struct WorkLogApp: App {
    @StateObject private var auth = BaiduPanAuthService()
    @StateObject private var sync = SyncEngine()
    var body: some Scene {
        WindowGroup("同笔记") {
            AppRoot()
                .environmentObject(auth)
                .environmentObject(sync)
        }
        .defaultSize(width: 1120, height: 700)
        .windowResizability(.contentMinSize)
    }
}
```

`AppRoot`：`Group { if auth.isSignedIn { MainView() } else { LoginView() } }`，`.frame(minWidth: 960, minHeight: 620)`，`.onOpenURL { auth.handleCallback(url) }`。**无 `.commands` / 自定义主菜单 / 全局快捷键**。

### 4.2 场景与通知联动（两层独立）

| 层 | 触发 | 动作 |
|---|---|---|
| AppRoot | `.task(id: auth.isSignedIn)` | 已登录 → `await auth.enforceDeviceSession()` |
| AppRoot | `scenePhase == .active && isSignedIn` | 再查一次设备会话 |
| AppRoot | `.onReceive(.tonoteDeviceKicked)` | `auth.signOutFromKick()` → 回登录页 |
| MainView | `.onAppear` | 选中失效时选第一条非快同步笔记 |
| MainView | `.task` 首次 | `syncRound` |
| MainView | `.task` 循环 | 每 45 秒（仅 `.active`）`syncRound` |
| MainView | `.onChange(scenePhase) == .active` | `syncRound` |
| MainView | `.onReceive(.tonoteLocalDataChanged)` | `sync.schedule(...)` 1.5 秒防抖 |
| MainView | `.onReceive(store.$notes)` | 选中笔记消失时回退 |
| MainView | `.onChange(selectedID)` | 非空时 `showTodos = false` |

**两个通知**：
- `.tonoteLocalDataChanged` = `"tonote.localData.changed"`（`SyncRules.swift:5`）：由 `SyncCursorStore.markDirty` 与 `NotebookStore.persist(dirty: true)` 发出；同步回写路径（`applySyncedNote` / `applySyncedTodo` / `setNotes` / `setTodos` / `NotebookStore.applyCloud`）**不发**，防止回环。
- `.tonoteDeviceKicked` = `"tonote.deviceSession.kicked"`（`DeviceSession.swift:5`）：由 `DeviceRegistry.ensureNotKicked` 的 `.kicked` 分支发出。

### 4.3 状态容器

`NoteStore` / `TodoStore` / `NotebookStore` / `AvatarStore` / `SyncEngine` / `BaiduPanAuthService` 均为 `ObservableObject` + `@Published`，无自定义 Combine `Publisher`/`Subscriber`（除 `SelectionFormatPanel` 的 `NSObjectProtocol` 观察者）。`NoteStore+Bindings.swift` 提供 `binding(for:)` 与 `contentBinding(for:)`，把 `@Binding` 的 get/set 同步接到 `note(with:)` / `update(_:)` / `updateContent`。

## 5. 数据模型设计

### 5.1 模型总表

| 类型 | 协议 | 关键字段 |
|---|---|---|
| `Note` | `Identifiable, Codable, Hashable` | `id/title/body/createdAt/updatedAt/deletedAt/tags/notebook/pinned/contentFormat/rev/purged`（12 键） |
| `Todo` | `Identifiable, Codable, Hashable` | `id/title/notes/status/plannedAt/completedAt/startedAt/createdAt/updatedAt/order/rev/purged` |
| `TodoStatus` | `String, Codable, CaseIterable` | `todo / doing / done / terminated` |
| `NoteContentFormat` | `String, Codable, Sendable` | `markdown / richText` |
| `NoteContent` | `Equatable, Sendable` | `body: String`、`format` —— 注释「两者必须一起写入」 |
| `RichTextBlockStyle` | `String, Codable, CaseIterable, Sendable` | `paragraph / heading1..heading6 / quote / code / bulletItem / orderedItem / table`（12 case） |
| `RichTextRun` | `Equatable, Sendable` | `text / isBold / isItalic / isUnderline / isStrike / fontSize / colorHex / backgroundHex / link / image` |
| `RichTextBlock` | `Equatable, Sendable` | `style / runs / listLevel / table`（`.table` 时 `runs` 为空） |
| `RichTextDocument` | `Equatable, Sendable` | `blocks: [RichTextBlock]` |
| `RichTextImage` | `Equatable, Sendable` | `path / width / height` |
| `RichTextTableCell` | `Equatable, Sendable` | `blocks / alignment / backgroundHex`（构造时过滤 `.table` 块，不嵌套表格） |
| `RichTextTable` | `Equatable, Sendable` | `rows / columnWeights / fullWidth` |
| `RichTextCellAlignment` | `String, Equatable, Sendable, CaseIterable` | `left / center / right / justify` |
| `RichTextCellColor` | 命名空间 enum | `normalized(_:)` → `#RRGGBB` 或 nil |
| `SyncCursor` | `Codable, Equatable, Sendable` | `baseRev / baseUpdatedAt / serverMtime / dirty / uploadedAttachments` |
| `DeviceRecord` | `Codable, Equatable, Identifiable, Sendable` | `deviceId / deviceName / sessionId / kicked`（snake_case CodingKeys） |
| `LocalDeviceIdentity` | `Codable, Equatable, Sendable` | `deviceId / sessionId / deviceName` |
| `AvatarPreset` | `Identifiable, Hashable`（**无 Codable**） | `id / glyph / isSymbol / color1 / color2` |

> **重要**：富文本/表格模型全部**不是 Codable**，持久化靠受控 HTML 字符串；只有 `Note` / `Todo` / 设备 / cursor 是 Codable。
> **不存在 `Notebook` / `Tag` / `DeviceSession` 三个独立类型**：笔记本由 `Notebooks` 常量枚举 + `Note.notebook: String` + `NotebookStore.[String]` 表达；标签就是 `Note.tags: [String]`；设备会话是 `DeviceRecord` / `DeviceIdentityStore` / `DeviceRegistry` 等类型的集合。

### 5.2 兼容解码（渐进升级）

`Note` 与 `Todo` 都自定义 `init(from:)`，新字段一律 `decodeIfPresent + 默认值`，`encode(to:)` 写出全部字段，实现「读入旧文件、写出新格式」：

| 字段 | 缺失默认 |
|---|---|
| `contentFormat` | **`.markdown`**（全链路的根，保证旧笔记零风险升级） |
| `tags / notebook / pinned / rev / purged / deletedAt` | `[]` / `"工作日志"` / `false` / `0` / `false` / `nil` |
| `Todo.status / notes / order / purged` | `.todo` / `""` / `0` / `false` |
| `DeviceRecord.deviceName / kicked` | `""` / `false` |

旧笔记升级时机：首次在富文本编辑器打开时按 `MarkdownConverter.toDocument` 渲染；编辑后 `persist` 写回 `NoteContent(body: html, format: .richText)`，经 `contentBinding` → `NoteStore.updateContent` 原子写入。

### 5.3 派生属性与删除语义

- `Note.isTrashed = deletedAt != nil`；`plainBody` 按 format 分派；`snippet` 用 `visibleText` 截 60 字、空则「空笔记」；`timeText` 今天/昨天 `HH:mm`，否则 `M月d日`。
- `NoteStore.activeNotes` = `!purged && !isTrashed` 按 `updatedAt` 降序；`trashNotes` 按 `deletedAt` 降序。
- **两级删除**：`moveToTrash`（软删除，笔记留在数组）→ `restore`；`permanentlyDelete` 置 `purged = true`（墓碑，不移除数组元素、不主动删网盘文件）+ 清理附件。
- **Todo 无回收站**：`remove` 直接 `purged = true`；`clearCompleted()` 批量打墓碑（UI 入口已移除）。
- 删除笔记本用 `moveNotes(from:to:)` 把笔记整体改归属，**不删笔记**；删除标签用 `removeTag` 从所有笔记移除，**不删正文**。

### 5.4 表格模型规则

| 项 | 设计 |
|---|---|
| 上限 | `maxRows = 100`、`maxColumns = 32`、`fixedColumnWidth: CGFloat = 100`；注释说明「上限不能等于工具栏选择器最大列数（8），否则建 8 列后点边沿加列被静默拒绝」 |
| `columnWeights: [Double]?` | 列宽权重和为 1；`nil` = 各列等宽。仅当 `count == columnCount` 且全 `> 0` 才保留；`insertColumn` / `removeColumn` 都置 nil |
| `fullWidth` | `true` = percentage 100（占满编辑区）；`false` = absolute `columns × 100`（固定列宽）。`init` 默认 `true`，但 `make(rows:columns:)` 新建表用 `false` |
| 矩形化 `init` | `columnCount = max(rows.map(\.count).max() ?? 1, 1)`；空 `rows` 补 1 行；每行不足补空单元格、超出 prefix 截断；每个 cell 过滤 `.table` 块并归一化颜色 |
| 增删行列 | `@discardableResult mutating -> Bool`；`insertRow` 沿用相邻行的 `alignment` 与 `backgroundHex`，`insertColumn` 沿用左邻列；`removeRow` 须 `rowCount > 1`，`removeColumn` 须 `columnCount > 1` |
| `plainText` | 单元格间 `\t`、行间 `\n` |

## 7. 受控 HTML 编解码协议

设计目标（`RichTextHTMLCodec.swift:3-8`）：**只允许一组固定标签与属性**，保证 ① 跨端解析一致；② 正文不出现 `file:///Attachment.tiff` 临时引用；③ 图片只以相对路径落盘。

### 7.1 编码（`encode(_:) -> String`）

| 规则 | 说明 |
|---|---|
| 块级标签 | `<p>` / `<h1>`…`<h6>` / `<blockquote>` / `<pre>` / `<table>`（委托 `RichTextTableCodec.encode`） / `<ul>` / `<ol>` / `<li>` |
| 连续同类列表项合并 | 合并为一个 `<ul>`/`<ol>`；`data-level` 仅当 `level > 0` 写出 `<li data-level="N">` |
| 标题抑制加粗 | `h1`–`h6` 编码时 `suppressBold = true`，段落内不再套 `<strong>`（语义冗余） |
| 块间分隔 | 以 `\n` 分隔，**最后一块不加尾随换行**（保证「编码→解码→编码」稳定） |
| `.table` 且 `table == nil` | 退化为 `<p></p>` |

**行内 run 编码顺序（由内到外固定）**：

```
1. 图片优先短路：<img src="…" width="…" height="…">   （width/height 无单位）
2. <a href="…">
3. <span style="font-size:…px">                        （font-size 带 px）
4. <span style="color:…">
5. <span style="background-color:…">
6. <s> → <u> → <em> → <strong>                        （最外层是 strong）
```

`formatNumber`：整数输出 `String(Int(value))`，否则 `String(format: "%.1f", value)`。

### 7.2 转义与实体

- `escapeText`：`&` `&lt;` `&gt;`；`escapeAttribute` 再加 `"` → `&quot;`、`'` → `&#39;`。
- 解码实体表**固定 7 项**：`&amp; &lt; &gt; &quot; &#39; &apos; &nbsp;`；`&nbsp;` 替换为普通空格 U+0020。**无通用 `&#NNN;` 数值解析**。
- `visibleText(_:)` 不建树，逐字符扫描跳过 `<…>` 片段，最后 `decodeEntities`；`reserveCapacity(min(html.count, 8000))`；供 `Note.snippet` 与字数统计使用（大表格也能立刻算完）。

### 7.3 解码（`decode(_:)`）

```
HTMLTreeBuilder.parse(html) → blocksFrom(node:) → 空则补 [RichTextBlock(style:.paragraph)]
```

| 标签 | 处理 |
|---|---|
| `table` | `RichTextTableCodec.decode(attributes:children:)` → `.table` 块 |
| `p` | `paragraphBlocks(from:)`，段落内 `<br>` 拆成多个段落 |
| `h1`–`h6` | 对应 heading 样式 |
| `blockquote` / `pre` | `.quote` / `.code`（pre 内容为 `rawText(children)` 单 run） |
| `ul/ol` | `listBlocks`：只认 `li`；`level = Int(data-level) ?? 0`，钳制 0…7 |
| 顶层 `br` | `[]` |
| 未知标签 | 递归 children，为空则 `rawText` 兜底成段落 |

行内识别：`strong/b`、`em/i`、`u/ins`、`s/strike/del`、`span` + `applyStyle`、`a[href]`、`img[src/width/height]`、`br → RichTextRun(text:"\n")`。
`applyStyle`：按 `;` 分段、`:` 以 `maxSplits:1` 拆分；`font-size` 去 `"px"` 且须 `> 0`；`color` 原样存；`background-color`/`background` 为空 / `transparent` / `none` → `nil`。

### 7.4 极简 HTML 解析器 `HTMLTreeBuilder`（private enum）

- 栈式 `Frame`；注释 `<!-- … -->` 整段跳过；结束标签取 `stack.lastIndex(where: { $0.tag == name })` 逐个弹栈；未闭合标签末尾依次弹栈。
- `isVoidTag`：`br, img, hr, meta, link, input, area, base, col, source`。
- `parseAttributes` 正则 `([A-Za-z_:][-A-Za-z0-9_:.]*)\s*=\s*("[^"]*"|'[^']*'|[^\s"'>]+)`；key 小写、值去引号并 `decodeEntities`。
- **`style` 多次出现合并（用 `;` 连接，避免字号与颜色互相丢失）**；其他属性重复时以**首个**为准（与浏览器一致）。

### 7.5 表格的受控 HTML

```html
<table data-widths="0.28,0.72" data-fullwidth="0">
  <tr><td data-align="center" data-bg="#F2F2F4">…内层复用正文标签…</td></tr>
</table>
```

| 规则 | 说明 |
|---|---|
| `data-fullwidth="0"` | **`<table>` 级属性**，仅当 `fullWidth == false` 才写；满宽是默认值、不写属性，保证老笔记编码结果完全一致 |
| `data-align` / `data-bg` | `<td>` 级；左对齐与无背景**不写属性** |
| 单元格内部 | `RichTextHTMLCodec.encode(RichTextDocument(blocks: cell.blocks))`，复用正文同一套段落标签 |
| 解码 | 认 `<tr>`，`<td>` **与 `<th>` 都认**；`fullWidth = attributes["data-fullwidth"] != "0"`；单元格 blocks 过滤 `.style == .table`（不嵌套表格） |
| 背景色兼容 | 优先 `data-bg`；否则从 `style` 定位 `background-color:`；支持 `#RRGGBB` 与 `rgb(r,g,b)`（按非数字切分取前 3 个、clamp 0…255、格式化 hex） |
| 对齐兼容 | `RichTextCellAlignment.fromHTMLAttributes` 同时读 `data-align` 与 `style="text-align:…"` |

### 7.6 Markdown 兼容（`MarkdownConverter`）

设计注释明确：「旧笔记里存在 `![](图片地址)` 这类占位符（不是真实附件），按纯文本处理，绝不把占位符误当成真实图片写进附件目录」。

| 行类型 | 输出 |
|---|---|
| 空行 | flush 段落/列表缓冲，分段 |
| ```` ``` ```` 围栏 | **整行丢弃**，不进入 code 块状态、不产出 `.code` |
| 标题 | 仅 `heading1/2/3`（按 `###`/`##`/`#` 匹配），四级以上不保留 |
| `- ` / `* ` / `+ ` | `.bulletItem` |
| `^\d+\.\s+` | `.orderedItem` |
| `> ` | `.quote` |
| 普通行 | 连续非空行**合并为同一个段落**，行间不插分隔符 |

行内：加粗、删除线、行内代码（→ `fontSize: 13`）、`![图片](路径)`（**仅当路径以 `attachments/` 开头**才转 `RichTextImage`，否则原样纯文本 run）、链接、斜体。

> **旧 Markdown 转换是有损简化**，不可当作无损 Markdown 引擎描述。

### 7.7 图片路径识别（`ImagePathScanner`）

纯 Foundation、跨平台共用。算法：起点必须是 `/` → 向前扫描找第一个 `.` 并校验扩展名在白名单（扩展名后不能紧跟字母/数字，防 `a.png2`）→ 向前回溯起点直到遇 `"`/`'`/`(`/`[`/`<`（因此**允许路径本身含空格**）→ 按斜杠边界从长到短尝试候选（剥离前面粘连的普通文字）→ `validatedImageURL` 要求 `FileManager.fileExists` 且不是目录。

## 8. 富文本编辑器内核设计

### 8.1 五段式结构

| 层 | 职责 |
|---|---|
| `RichTextEditor`（`NSViewRepresentable`） | 创建 `NSScrollView` + `RichTextNSTextView.makeTextKit1()`；关闭四种自动替换；`textContainerInset = 24×24`（给表格灰圆留位置）；绑定 controller/附件仓库/笔记 ID；注册滚动通知与粘贴回调 |
| `Coordinator`（`NSTextViewDelegate`） | `textDidChange` / `doCommandBy` / `shouldChangeTextIn` / `textViewDidChangeSelection` / 选区浮窗定位；持有 `isUpdatingProgrammatically`、`weak textView`、`representedNoteID`、`loadedBody`、`selectionWork` |
| `RichTextEditorController`（`ObservableObject`） | 命令层；`@Published currentBlockStyle / currentListLevel / tableCaret / currentCellAlignment`；`commitChanges()` 只调 `onContentChanged?()` |
| `RichTextNSTextView` | TextKit 1 装配、粘贴/拷贝/keyDown 拦截、表格边沿遮罩层、灰圆命中、大表格补排、滚动原点锁定、诊断日志 |
| 纯函数层 | `RichTextBridge`（模型↔`NSAttributedString`）、`RichTextTableLayout`（表格排版/读回）、`RichTextTableEditor`（结构编辑）、`RichTextTableGutterGeometry`（几何）、`RichTextTableCellMenu`、`RichTextTableDebug` |

### 8.2 载入 / 回写闭环与四重隔离

**避免「载入即改写正文」的三层保护**：
1. `load` 全程包在 `isUpdatingProgrammatically = true/false` 之间，`persist` 首行 guard 拦截。
2. `load` 本身**不写** `parent.content`、不调 `commitChanges()` / `persist`，只更新 `loadedBody`。
3. `persist` 先 `loadedBody = html` 再写 `parent.content`；SwiftUI 触发 `updateNSView` 时两者相等，不会再 load。

**四条回写触发**：
- 文字输入：`textDidChange` → `persist(from:)`。
- 属性类命令：`NSTextStorage` 属性变更**不保证**触发 `textDidChange`，故由 `controller.commitChanges()` → `onContentChanged` → `coordinator.persist(from:)` 显式写回。
- 插入图片：编程式 `insertText` 后显式 `commitChanges()`。
- 表格结构编辑：`didChangeText()`。

> `RichTextEditorController.swift:8` 的文件头注释仍写「命令执行后触发 textDidChange」，属旧描述，与真实主链路有落差。

**多个编辑器实例互不干扰的四重校验**：
- 笔记 ID：`parent.noteID != representedNoteID` 判定切换笔记，取消 `selectionWork`、清 `loadedBody`；`persist` guard 要求相等。
- 视图身份：`tv === textView`（弱引用）。
- 每次 `update` 重新绑定 `controller.textView / attachments / noteID` 与粘贴回调（避免指向旧笔记附件目录）。
- 边沿点击就地绑定：`mouseDown` 命中灰圆后先 `controller.textView = self` 再执行插入（SwiftUI 复用编辑器时 controller 可能还指向旧视图）。

**`persist` 内的修补**（在 `isUpdatingProgrammatically` + `undoManager.disableUndoRegistration()` 包裹内）：`repairIdentity`（表格 ID 扳回同一张表）、`normalizeListMarkers`（列表标记重建）、`separateFromBodyText`（表格下方段落间距）。

### 8.3 段落与列表设计要点

| 项 | 设计 |
|---|---|
| 字号阶梯 | 正文 14（常规）/ H1 40 / H2 32 / H3 24 / H4 18 / H5 16 / H6 14；`code` 用等宽 `monoFont`。H5/H6 只为兼容旧笔记 |
| 旧文档兜底 | `resolveStyle` 无 `blockStyle` 属性时用粗体 + 字号阈值推断：`>=34 → H1`、`>=27 → H2`、`>=21 → H3`、`>=17 → H4` |
| 切样式清粗体 | 切到正文/引用/代码块/列表时强制 `bold = false`、字号重置、斜体保留；切到标题强制加粗 |
| 编号体系 | `orderedLabel(level % 3)`：`0 → 1.`、`1 → a..z`（aa/ab 双字母）、`2 → 小写罗马`；序号固定常规字重 |
| 圆点 | 父子共用 `•`，靠 `NSStrokeWidthAttributeName = 2.5`（字号百分比）+ `.strokeColor` 变空心；字号 `max(9, baseSize-2) * 1.5` |
| 缩进 | `listIndent = 4 + min(max(level,0),7)*32`，`listTextOffset = 15`，`tabStops = [textIndent, textIndent+14]` |
| 编号顺延 | `markerPlan(for:)` 用 8 级 counters + `paragraphGap`；中间只隔 1 段正文时顺延上方，隔多段/标题/引用/代码块/无序列表重新从 1 开始 |
| 标记不进 HTML | `RichTextKeys.listMarker` 是视图层前缀，`document(from:)` 跳过；层级存 `<li data-level>` |
| 防御 | 标记范围用结构化扫描（合法字符 + 遇 `\t` 结束 + 最多 8 字符），**不用 `effectiveRange`**；末尾 `\t` 强制正文属性；清理 `typingAttributes` 里的 `listMarker` / `.strokeWidth` / `.strokeColor`；`normalizeListMarkers` 跳过表格段落 |

### 8.4 图片链路设计

```
三入口：keyDown 拦 Cmd+V / paste(_:) / pasteAsPlainText(_:)
  ↓ handlePaste
分支顺序：
  1. 图片文件 URL（NSURL + NSFilenamesPboardType 兜底）
  2. 路径文本（ImagePathScanner.containsImagePath → onPasteText）
  3. 剪贴板实际声明类型的 data(forType:)（UTType.conforms(to:.image) + 关键字宽松识别）
  4. NSImage(pasteboard:) 兜底 → pngData
  5. RTFD（com.apple.flat-rtfd / NeXT RTFD pasteboard type → NSAttributedString → fileWrapper.regularFileContents）
  ↓ writeTemporaryImage
立即 NSImage(contentsOf:) 校验 → 失败删掉并 normalizedPNG 统一转 PNG 再写、再校验
  ↓ 导入 attachments/ + 相对路径写进正文
失败：onPasteFailure → onEditorError → EditorView.activeDialog = .failure → 弹「操作失败」
```

**关键约束**：
- 读取失败**必须弹错误提示**（带剪贴板实际类型清单），**绝不回落到 `NSTextView` 默认粘贴**（会产生 `file:///Attachment.tiff` 临时引用，序列化后图片丢失）；任何分支都不能静默 return。
- 从笔记里右键「拷贝」图片时剪贴板只有 RTFD、没有任何位图类型，故必须 override `copy(_:)`，选区纯图片时直接写 `public.png`。
- 全链路 `[TNPaste]` 日志同时 `NSLog` 与写 `paste-debug.log`（沙盒终端 `log show` 不可用，故落文件）。
- `RichTextKeys.imagePath` 保证序列化只记相对路径；`fittedBounds` 以文件真实尺寸为准（避免历史污染值形成自我循环），上限 480pt，读图失败退化 160×90。

### 8.5 颜色设计

`hexString(from:)` / `color(fromHex:)` **必须用 sRGB 构造**（`RichTextBridge.swift:67` 注释：「calibrated 色彩空间转换后会偏移，十六进制无法精确往返」）。`document(from:)` 回读时仅当颜色 ≠ `defaultTextColor` 才记 `colorHex`；`backgroundColor` 要求 `alphaComponent > 0.01`；`fontSize` 仅当与 `baseSize` 相差 > 0.01 才记。

### 9.1 TextKit 1 装配

```swift

`textContainerInset = NSSize(width: 24, height: 24)`：左右 24pt 给左侧加行灰圆、上方 24pt 给加列灰圆/蓝圆留位置。

### 9.2 `NSTextTableBlock` 与自定义属性

`RichTextTableLayout.attributedString(for:attachments:)`：一个 `NSTextTable`（`numberOfColumns`、`collapsesBorders = true`、`hidesEmptyCells = false`），每格一个 `NSTextTableBlock(table:startingRow:rowSpan:1:startingColumn:columnSpan:1)`；`applyChrome` 设 padding minX/maxX=10、minY/maxY=6、border=1、borderColor `0xD9DADF` 系、`verticalAlignment = .topAlignment`。

每个单元格段落写入 4 个自定义属性：

| Key | 用途 |
|---|---|
| `WorkLogTableID` | 表格身份，`repairIdentity` / `unified` 靠它把回车复制出的新 `NSTextTable` 对象扳回同一张表 |
| `WorkLogTableColumnWeights` | 列宽权重 |
| `WorkLogTableCellBackground` | 单元格背景色 |
| `WorkLogTableFullWidth` | 是否满宽 |

`tableTopMargin = 20`、`tableVerticalMargin = 10`；`separateFromBodyText` 给表格下方段落设 `paragraphSpacingBefore = max(natural, tableVerticalMargin + 2)`。

### 9.3 就地改属性 vs rewrite（核心区分）

| 类别 | 实现 |
|---|---|
| `setAlignment` | 只改目标段落 `.paragraphStyle` 的 `alignment`；改段落样式走 `keepingTable` 保住 `textBlocks` 与 `alignment` |
| `setCellBackground` | 直接改 `NSTextTableBlock.backgroundColor` + 写/删 `cellBackgroundKey`，用 `paragraphStyle.mutableCopy()` 重新写入触发重排，但 `textBlocks` 仍是**同一个 block**（contentWidth / padding / border 全不变） |
| `setWidthMode` | 就地 `table.setContentWidth(100, .percentageValueType)` 或 `columns*100, .absoluteValueType`，按权重分摊每列，写 `fullWidthKey` |
| `isFixedWidth` | `block.contentWidthValueType == .absoluteValueType`。`read` / `unified` 在属性缺失时用 `declaredFullWidth ?? !fixedWidth` 兜底，**否则固定 100pt 表格会被误读成满宽，设置单元格后宽度突然变大** |
| rewrite | `insertTable` / 增删行列 / `deleteTable` / 末格 Tab：`allowsStructuralEdits = true` → `shouldChangeText` → `replaceCharacters` → `moveCaret` → `didChangeText()` |
| 保护 | `shouldAllowChange` 只有选区**完整覆盖**整张表才允许删；`normalizeListMarkers` 跳过表格段落（重写标记会冲掉 `NSTextTableBlock`） |

### 9.4 边沿 gutter 设计

**绘制层 `RichTextTableGutterView`**：`isFlipped = true`、`isOpaque = false`、`hitTest` 恒返回 `nil`（事件穿透）。依次绘制常驻小灰圆 `r=3.2` → 当前格右上角 16pt 下箭头 → hover 引导线（accent 45% 透明矩形，宽 1.5，贯穿整表高）→ 蓝色圆 `radius=10` + 白色加号 `arm=4.2`。**按需求不显示文字浮窗**。

**几何常量（当前磁盘）**：

| 常量 | 值 | 依据 |
|---|---|---|
| `columnLeadingInset` / `columnTrailingInset` | 5.5 | `collapsesBorders` 让相邻两格共用边框，可见竖线落在 11pt chrome 中点 |
| `verticalChrome` | 7 | TextKit 对上下边框不合并，仍取完整 6+1；写成 3.5 会让加行圆比横线低 3.5pt（截图实测） |
| `dotInset` | 12 | 列圆在表格顶边上方 |
| `tableLeadingMargin` | 16 | 加行圆 x 锁在 `bodyTextMinX`（正文首字左缘） |
| `dotHitRadius` | 22 | 蓝色加号半径 10，实际点击常落在圆心偏表格一侧 15–20pt |
| `menuRect` | `(rect.maxX-19, rect.minY+3, 16, 16)` | 单元格右上角下箭头 |

**几何计算 `RichTextTableGutterGeometry.layout(in:)`**：列灰圆 `(edge, bounds.minY - dotInset)`；`tableFrames` **只读已排完的行框**（`glyphRange(forBoundingRectWithoutAdditionalLayout:)`，主动 `glyphIndex` 会把没排完的格子排一半、边框会断），按 `tableKey` 分组、同格多 fragment 取 `union`；`completeRows` 要求一行每列都有行框；整行合成一条 fragment 时用 `splitColumns` 按 `data-widths` 权重或等宽切列；行边界非递增时按行高均分。

**命中与事件**：`dot(at:in:)` 用主轴权重加倍 `score = primary*2 + secondary` 解决左上角 column/row 两圆互抢；`borderCursor(at:in:)` `slop=4` 给列宽拖拽光标。`mouseDown` 顺序：① `dot(at:)` → ② 未命中且落在 `menuRect.insetBy(-3,-3)` → 弹单元格菜单 → ③ `activeDot` 兜底（`dx<=22 && dy<=22`）→ ④ miss 记日志后 `super.mouseDown` → 命中后**在被点击的 self 上直接执行插入**并校正 `controller.textView = self`。`finiteInt` 防坐标无穷大触发 `Int(...)` 主线程陷阱闪退。

**滚动与补排**：`reflectScrolledClipView` 在横向滚动后重算几何；`rebuildTableRowSpans` / `scheduleTableRowFill` / `fillOneTableRow` 每主队列回合只补一整行（间隔 0.016s）；`refreshTableGutter` 合并同一轮的改尺寸/滚动/载入。

**光标**：tracking area 加 `.cursorUpdate`，重写 `cursorUpdate(with:)`；命中灰圆/蓝圆/下箭头 `NSCursor.pointingHand.set()`，边框拖拽光标，其余 `NSCursor.iBeam.set()`。

> **历史踩坑（不要重犯）**：`stickyRowX = max(textView.visibleRect.minX, 0) + 14` 吸附视口左缘 —— `visibleRect` 初始布局未稳定返回非 0 偏移，且其坐标空间与 gutter 绘制 / `convert` 的 hit-test 不一致，产生「画在左、命中在右」的水平错位与「点一下才归位」。现统一使用与加列圆同一套表格几何/文档坐标。

### 9.5 单元格菜单与上限

`RichTextTableCellMenu.show`：20 色色板（首个 `nil` = 无颜色，白圆 + 斜杠；其余 19 色），`PaletteView` 5 列 × 20pt 色块，`isFlipped = true`；菜单项含「单元格背景」标题（禁用）、「匹配笔记宽度」复选、「删除选中的列 / 行 / 删除表格」。`currentActions` 静态强引用避免菜单跟踪期间被释放；`targetCells` 在菜单打开时冻结选中格子；`focusCell()` 在执行依赖选区的删除命令前把光标放回目标格。`MenuActions` 直接调 `controller`，不经 SwiftUI。

### 10.2 上传 / 下载链路

**上传 `uploadData(_:to:accessToken:)` 三步**：

```
1) precreate  POST xpan/file?method=precreate
   form: path, size, isdir=0, autoinit=1,
         block_list = percentEncoded(["<每片MD5>",...]), rtype=3
   分片 = UploadChunks.slices(data)，byteSize = 4 MiB
   MD5 = 每片 CC_MD5（非整文件），CommonCrypto，小写 hex
   成功判定：拿到 uploadid 且 (errno ?? 0) == 0
   uploadid 兼容 String / Int64；block_list 兼容 [Int] / [String]
2) 分片上传 / 秒传
   return_type == 2 → 秒传，跳过全部分片
   否则只传 pre.blockList 指定序号（未返回则传全部），where indices.contains 越界保护
   uploadBlock：POST superfile2?method=upload&type=tmpfile&path&uploadid&partseq
                multipart/form-data 字段名 file、filename="blob"
                User-Agent: pan.baidu.com
                HTTP >= 300 或 errno != 0 → 抛错附响应体
3) create     POST xpan/file?method=create
   form: path, size, isdir=0, uploadid, block_list, rtype=3
   非 JSON 响应 → 抛错；errno != 0 → 抛错（不解析 fs_id/path/ctime）
```

`postForm` 统一 `User-Agent: pan.baidu.com` + HTTP 状态检查；`bodySnippet(_:)` 取响应前 300 字符拼进错误消息（用于 listFilePage / deleteRemote / downloadData / precreate / create / postForm / uploadBlock）。

**下载 `downloadData(_:accessToken:)`**：

```
GET xpan/file?method=download&access_token&path&threshold=0
  → 解析 DlMeta { errno, list: [{ dlink }] }
  → 响应不是 JSON（多为风控/网关 HTML）→ 抛 server 并带原文
  → JSON 但 errno != 0 或缺 dlink → 抛 notFound
  → 给 dlink 追加 access_token，带 User-Agent: pan.baidu.com 拉取
  → HTTP >= 400 → 抛错附响应体
```

`deleteRemote` 把 `errno == -9` / `31066` 视为「文件不存在/已删除」白名单。`listFiles` 分页 `limit=200`，`while start < 5000`（上限约 5000 条）。

### 10.4 同步主流程与合并决策

```
syncRound(store:todos:onlyNoteID:):
  status.isSyncing → needsAnotherRound = true; return
  status = .syncing; lastMessage = nil; kicked = false
  token = validToken()
  DeviceRegistry.shared.ensureNotKicked(accessToken:)      // 每轮开头
  noteCount = syncNotes(...)
  if onlyNoteID == nil { syncNotebooks(); syncTodos() }   // 单篇同步跳过这两项
  status = .success(date); lastSyncDate = date
  lastMessage = 全量「笔记 N 篇 · 任务 M 条」/ 单篇「已同步本篇」
  catch DeviceSessionError.kicked → 被踢文案，且不补跑一轮
  catch → .failed(error.localizedDescription)
  needsAnotherRound && !kicked → 递归再跑一轮（最多补一轮）
```

**`SyncRules.afterFetch` 决策表**（`dirty` = 本机有未上传修改）：

| 条件 | 决策 |
|---|---|
| `remote == nil` | `.upload(rev:)`，`rev = baseRev == 0 ? 1 : baseRev + (dirty ? 1 : 0)`，再 `max(rev,1)` |
| 从未同步（`baseRev == 0 && baseUpdatedAt == nil`）且本地无 | `.useRemote` |
| 从未同步且 `sameTime(remoteUpdatedAt, localUpdatedAt)` | `.useRemote`（避免把同一篇拆成冲突副本） |
| 从未同步且两边时间不同 | `dirty ? .conflict : .useRemote` |
| `!dirty` | `changed ? .useRemote : .rememberMtime` |
| `dirty && !changed` | `.upload(rev: baseRev == 0 ? 1 : baseRev + 1)` |
| `dirty && changed` | `.conflict` |

其中 `changed = remoteRev != baseRev || baseUpdatedAt == nil || !sameTime(remoteUpdatedAt, baseUpdatedAt!)`；`sameTime` 容差 1 秒；`remoteWins(local:remote:)` 用 `>=`（平局云端胜）。`shouldSkipFetch`：`!cursor.dirty && serverMtime == cursor.serverMtime` 时跳过下载（增量优化）。

**`SyncStep` 五值**：`skip` / `rememberMtime` / `useRemote` / `upload(rev:)` / `conflict`。

> 结论：**三方对照**，不是简单 last-write-wins。`rev` 判断云端是否变化，`updatedAt` 定冲突胜负，`cursor` 记上次同步基线。

### 10.5 发布、冲突、墓碑、cursor

- `publish(note:rev:cursor:...)`：最多 3 次；每轮 `ensureNotKicked` → 设 `publishing.rev = nextRev` → 上传附件 + 上传 note → **回读校验** `rev` 相等且 `sameTime(updatedAt)` → 成功则更新 cursor、可选删孤立附件目录、`applySyncedNote`、`note = publishing`；失败再跑 `afterFetch` 决定下一 rev 或转冲突；3 次失败抛「笔记「X」连续三次没能写上云端」。`publishTodo` 同构。
- `conflictCopy(of:)`：新 `UUID()`、标题若不以「（冲突副本）」结尾则追加、`rev = 0`、`purged = false`。
- `resolveConflict`：`remoteWins` → 本地另存副本上传（`rev:1`），原 ID 收下云端；否则云端另存副本，本地以 `max(local.rev, remote.rev) + 1` 上传为赢家。
- 墓碑 `purged`：`publish` 分支只上传带 `purged = true` 的 JSON（跳过附件）；成功后若无其他未 purged 笔记正文引用 `attachments/<id>/`，则 `try? deleteRemote` 删整目录。`NoteStore.applySyncedNote` 同理做本地附件清理。
- `SyncCursor` 五字段：`baseRev`（云端版本基线）、`baseUpdatedAt`（时间基线）、`serverMtime`（增量跳过）、`dirty`（本机有未上传修改）、`uploadedAttachments`（已上传附件清单，避免重复上传）。**只落本机，不上传**；换设备/重装后 `baseRev = 0`，靠 `neverSynced` 分支按 `updatedAt` 兜底。
- 附件：正文正则 `attachments/[0-9A-Fa-f-]{36}/[0-9A-Fa-f-]{36}\.[A-Za-z0-9]+` 提取路径，`Set` 去重保序；下载失败返回 `false` → 置 `cursor.serverMtime = nil` 让下轮重试。任务备注图片共用 `attachments/`（`uploadTodoImages` / `downloadTodoImages`）。

### 10.6 同步触发与状态

| 触发 | 周期 |
|---|---|
| App 启动 / 回前台 | 立即 |
| 定时（`scenePhase == .active`） | 45 秒 |
| `.tonoteLocalDataChanged` 防抖 | 1.5 秒 |
| 任务变更 `scheduleAutoSync` | 1.2 秒（若上轮在跑，每 0.5 秒等待最多 20 次） |
| 手动按钮 | 立即 |

`Status = idle / syncing / success(Date) / failed(String)`；`lastSyncDate.didSet` 写 `UserDefaults["tonote.lastSyncDate"]`。单篇失败用 `firstError` 收集，遍历完所有 ID 后统一抛出，不因单篇失败中断整轮；`kicked` 错误单独上抛。失败**不退出登录**。

### 10.7 设备会话设计

```
DeviceRecord.decision(localDeviceId, localSessionId, remote):
  remote == nil || remote.deviceId != localDeviceId  → .publish
  remote.kicked && remote.sessionId == localSessionId → .kicked
  !remote.kicked && sessionId == localSessionId       → .unchanged
  其它                                                → .publish
```

- `DeviceIdentityStore`（`NSLock` + `@unchecked Sendable`）本地 `device.json`；设备号 UUID 生成后不变，退出登录不删除；`updateSession` 只换 sessionId。
- `beginLogin()`：换新的 sessionId 并覆盖写自己的 `devices/<本机ID>.json`（`kicked: false`）。**不遍历、不修改其他设备文件**。
- `kick(deviceId:)`：把对方文件 `kicked` 置 true（`markedKicked()` 只改这一字段、保持 sessionId 不变），不改本机文件；不能踢自己；`isSafeDeviceId` 正则 `^[A-Za-z0-9-]{8,80}$`。
- `ensureNotKicked`：打开 App / 回前台 / 每轮 `syncRound` / 每次 `publish` / 头像上传时调用；`.kicked` → 发 `.tonoteDeviceKicked` + 抛错 → `signOutFromKick()` → 回登录页 banner。
- **准确语义**：没有自动互踢；是「手动下线设备 + 被标记设备下次校验时自我登出」，且被下线设备重新登录即可自行解绑（`decision` 在 sessionId 不同时返回 `.publish`，把 kicked 覆盖回 false）。
- 头像与设备清单**独立于 SyncEngine**，不参与 `syncNotes`/`syncTodos` 合并。

### 11.2 侧栏三档与浮窗

### 11.4 弹窗状态机设计

多个 `.alert` 串在同一 SwiftUI 视图上只有部分生效（历史表现为「操作失败」提示完全弹不出来、粘贴失败「没反应」）。解决方案：`SidebarView` 与 `EditorView` **各自**一个 `@State activeDialog`（各 4 个 case）+ 单一 `.alert`。

| 视图 | case |
|---|---|
| `SidebarView.SidebarDialog` | `deleteTag(String)` / `newNotebook` / `notebookError(String)` / `deleteNotebook(String)` |
| `EditorView.EditorDialog` | `addTag` / `insertLink` / `failure(String)` / `deleteConfirm(DeleteAction)` |

另有独立状态：`MainView.showSync`（全工程唯一 `.sheet`）、`NoteListView.confirmDeleteID`、`SidebarView.showAvatarPicker`、`TodoView.imageError` / `showCalendar`、`SyncView.pendingKick` 等。全工程 `.popover` 7 处、`.alert` 5 处、`.contextMenu` 4 处、AppKit `NSMenu` 1 处、`NSOpenPanel` 1 处（复用）。

**先关再弹技巧**：新建笔记本失败时先 `activeDialog = nil`，再 `DispatchQueue.main.async { activeDialog = .notebookError(error) }`（`SidebarView.swift:313-317`）。

### 11.5 选中文字浮动窗口（关闭但保留）

`SelectionFormatPanel.isEnabled = false`；`show(at:bar:)` 首行二次保险；`EditorView` 在开关为 false 时**根本不注册** `onSelectionChange` 回调。内核侧选区监听（`textViewDidChangeSelection` / `scrollViewBoundsChanged` / `evaluateSelection` 0.25s 防抖 / `selectionScreenRect`）与 `SelectionFormatBar` 全部代码保留。`NonActivatingPanel.canBecomeKey/canBecomeMain = false` 保证不抢第一响应者。

## 12. 并发、通知与生命周期

| 层 | 并发设计 |
|---|---|
| `NoteStore` / `TodoStore` / `NotebookStore` / `SyncCursorStore` | **无 `@MainActor`、无锁、无队列**；CRUD 直接改 `@Published` 数组并**同步**执行 `save()`（`.atomic` 写盘在调用线程）。推断为「隐含 UI 主线程调用」假设，代码无显式保证 |
| `SyncEngine` | `ObservableObject`，`schedule` / `quickSync` / `syncSingleNote` / `syncRound` 标注 `@MainActor`；`needsAnotherRound` 单个 Bool 合并并发 |

| `DeviceIdentityStore` / `DeviceRegistry` | `@unchecked Sendable` + `NSLock`；`DeviceRecord` / `LocalDeviceIdentity` / `SyncCursor` 显式 `Sendable` |

### 15.2 结构性限制

- 置顶不参与排序键（仅「最近更新」下因刷新 `updatedAt` 间接置顶）。
- 回收站视图下搜索/笔记本/标签过滤被跳过，但搜索框仍可输入。
- 无批量操作、无拖拽排序、无深色模式、无统一设计令牌。
- 无本地自动备份，只有 `.atomic` 原子写入。
- 本地 Store 无显式并发保证（§12）。
- `SyncCursor` 只落本机，`server_mtime` 精确相等才跳过下载。
- 平局方向不一致：`SyncRules.remoteWins`（`>=`，云端胜）与 `mergeByUpdatedAt`/`mergeTodos`（`>=`，本地胜）分别在冲突与迁移两阶段。

- 冲突副本每次新建 UUID，反复冲突会产生多份副本。

- `EditorView.swift:518-521` `formatButton` 的 `ToolbarAction` 参数未使用。
- 无 `Cmd+B/I/U`、`Cmd+N` 显式绑定；Esc 关闭 sheet 是系统默认。

### 15.3 「绝不静默失败」的实际落地情况

明文约定出自项目记忆（富文本粘贴链路与表格上限），主要落在：

1. `bodySnippet(_:)` 把服务端原始响应前 300 字符拼进所有关键错误消息。
2. `postForm` / `uploadBlock` / `downloadData` 对 HTTP >= 300/400 与 `errno != 0` 均抛错附响应体。
3. `syncNotes` / `syncTodos` 用 `firstError` 收集单篇失败并在整轮结束后 `throw`。
4. `publish` / `publishTodo` 三次写不上云端抛明确错误。
5. 下载附件失败返回 `false` → 置 `serverMtime = nil` 让下轮重试。
6. 所有错误进入 `SyncEngine.status = .failed` + `lastMessage`，由 `SyncView` / `EditorView` 对用户可见；设备被踢有独立通知与登录页 banner。
7. 图片粘贴失败弹「操作失败」并带剪贴板类型清单，绝不回落系统默认粘贴；表格撞上限 `NSSound.beep()` + 日志。

**但同步/登录链路仍存在多处「有意静默忽略」**（宜区分「致命错误」与「非致命降级」）：

| 位置 | 行为 |
|---|---|
| `BaiduPanConfig.swift:36` | secret 读取/解码失败 `return nil`，无日志 |
| `BaiduPanClient.swift:223` | `ensureRemoteDir` `_ = try? await ...`（死代码） |
| `BaiduPanClient.swift:247-251` | JSON 但 `errno != 0` 一律折叠为 `notFound`（可能吞掉权限/风控错误） |
| `BaiduPanClient.swift:422-425` | 分片上传非 JSON 200 响应不报错 |
| `BaiduPanAuthService.swift:97` | 回调无 `code` 静默 `return` |
| `BaiduPanAuthService.swift:118-122` | `finishSignIn` 忽略设备登记失败 |
| `BaiduPanAuthService.swift:134-136,148-150` | 离线不退出；`loadAccount` 忽略失败 |
| `SyncEngine.swift:328` | 附件本地文件不存在 → `continue` |
| `SyncEngine.swift:354-359` | 附件下载 `notFound` → `continue`；其他错误仅 `complete = false` |
| `SyncEngine.swift:245` | purged 后删除孤立附件目录 `try? await ...` |
| `AvatarStore.swift:81-83` | 云端头像拉取失败保持默认 |

`SyncEngine.swift:5` 类注释明确「失败只留到下一轮，不因此退出登录」——即同步失败在产品语义上被定义为**可重试降级**。

## 18. 附录 C · 术语表

| 术语 | 含义 |
|---|---|
| 按篇同步 | 每篇笔记/每条任务一个云端 JSON 文件（相对旧的单 `manifest.json`） |
| `SyncCursor` | 本机保存的同步基线对照表（不上传），含 rev / updatedAt / mtime / dirty / 已传附件 |
| `rev` | 已成功写到云端的版本；本机编辑不增加，上传成功才 +1 |
| `purged` | 彻底删除后留在数据里的墓碑；界面不再显示，远端文件先不删 |
| `deletedAt` | 软删除（移入回收站）标记 |
| 受控 HTML | 只允许固定标签与属性的 HTML 子集，保证跨端一致 |
| `listMarker` | 列表编号/圆点的视图层前缀属性，不写进 HTML |
| `keepingTable` | 改段落样式时保住 `textBlocks` 与 `alignment`，避免表格散架 |
| `isFixedWidth` | 从 `NSTextTableBlock.contentWidthValueType == .absoluteValueType` 推断表格是否固定列宽 |
| gutter | 表格边沿的自绘遮罩层（灰圆 / 蓝圆 / 引导线 / 下箭头） |
| 快同步 | 固定 UUID 的虚拟笔记，是「单篇同步」的 UI 载体（≠ `SyncEngine.quickSync` 的全量同步） |
| 快任务 | 任务页在笔记列表里的固定卡片名（页头标题叫「任务」） |
| 墓碑 | `purged = true` 的记录，用于让其他设备知道「已删除」 |
