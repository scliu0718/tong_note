一、先说诊断结论

用户反馈「Windows 版本中数据没通，需要使用真实百度网盘的数据」。逐项核对后，正式版本来就指向生产目录，之前的 89 项功能测试才是隔离在 __selftest__ 沙箱里。数据层面的实际状况如下：

检查项结果说明
正式进程远端根/apps/tong_log用户级 / 系统级环境变量里均无 TONOTE_REMOTE_ROOT、TONOTE_DATA_ROOT
生产 notes/32 篇本地 notes.json 也是 32 篇，ID 集合完全一致，逐篇标题比对一致
生产 todos/8 篇重启同步前本地只有 5 条 —— 这是「没通」的直接证据
Mac 旧 manifest.json全覆盖edydeMacBook-Pro 于 11-10 写入的 23 篇笔记 + 5 条待办，本地缺失 0
登录令牌有效%LOCALAPPDATA%\tonote\baidupan-token.json，未过期
当时运行的 GUI旧构建11-15 14:30 启动（UI 线程死锁修复之前），最后一次同步停在 14:33，之后约 10 小时无变化
为什么看起来「没通」：旧进程内存里跑的是修复前的代码，首轮同步会卡住；它不会自动加载新编译的 DLL。所以云端新增的 3 条待办一直没下来，而状态栏又显示「笔记 0 篇 · 任务 0 条」——这个 0 其实是本轮变更数，不是数据总量。

二、发现并修掉的三个问题

#问题处理文件
1空数据目录首次启动会灌入 7 篇 NoteSamples 演示笔记，登录后被当成「本地新增」推上云端，和真实笔记混在一起改为保持空列表，由同步引擎从真实网盘拉取；示例数据仅在显式调用时写入Storage/NoteStore.cs
2同步成功文案「笔记 0 篇 · 任务 0 条」容易被读成「没有数据」；非 0 时也没说明是变更数0 时补「无变更，已与网盘一致」，非 0 时标「条变更」Sync/SyncEngine.cs
3实连新缺陷 直链下载偶发 HttpRequestException（每轮命中的文件还不一样），单篇失败会让整轮同步漏数据下载失败时重取一次直链再试，与既有 404/31066 分支共用重试上限；用户取消不重试Baidu/BaiduPanClient.cs

第 3 项是新增的生产只读验收跑出来的：首轮 H04 挂了一篇笔记、次轮 H07 挂了一条待办，两次失败文件不同，据此判定为直链网络瞬态而非坏数据。修复后连跑三轮均全绿。
