# 同笔记 PC 版（Windows）需求文档

> **文档性质**：面向 PC 端（Windows 10/11 桌面）的产品需求规格，用于研发、测试、验收。  
> **编写依据（唯一基准 = Mac 版）**：以 macOS 版（`mac_tonote`，已本机构建、启动并逐屏核对，记录见附录 D）为功能与交互的**唯一基准**，辅以 `docs/设计文档.md`、`docs/功能点文档.md`、`docs/用户使用文档.md`、`同笔记-Mac端UI设计.html`、`docs/guide/images/*.png`（6 张界面图）。**第 5~9 章与附录的所有需求均由 Mac 行为推导，与 Windows 现状无关**；第 11 章对 `windows_tonote` 现状的描述仅是**未经实测的参考线索**，不得据此删减需求——Windows 开发应以第 5~8 章逐条对照实现，用第 12 章验收。  
> **基准快照**：2026-11-18。Mac 源码口径为 `功能点文档.md` 的 176 个功能点 + 之后合入的「页面范围同步」改造（`SyncScope` 队列、笔记 30 秒 / 快同步 15 秒节流、任务保存即传、任务字段三方合并）。  
> **读法**：第 1~4 章讲「做什么、给谁用、长什么样」；第 5 章是逐条需求（编号 `PC-xx-nn`，含优先级与验收标准）；第 6~8 章是数据、同步、视觉规格；第 9 章是非功能需求；第 10 章是 Mac → PC 的刻意差异；第 11 章是现有 Windows 工程的完成度与缺口；第 12 章是验收清单；第 13~14 章是里程碑与风险。  
> **优先级**：`P0` = 上线必备（缺失则不可用 / 会丢数据）；`P1` = 上线应有（体验完整）；`P2` = 增强（可后置）。  
> **两条硬规则**：① **数据格式与云端目录是三端契约，PC 端不得单方面改动**；② **「绝不静默失败」**：任何会让用户以为成功、实际失败的路径，必须有可见反馈或日志。

## 1. 产品定位与范围

### 1.1 产品一句话

**同笔记**是「数据属于你自己」的跨端笔记：笔记、表格、任务和附件直接存放在**用户自己的百度网盘**（应用目录 `/apps/tong_log`），不建服务器、不订阅、不锁数据；Mac / Windows / Android（以及 iOS）通过同一套云端文件契约互通。

### 1.2 PC 版目标

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 与 Mac 版**功能等价、数据互通**：同一份网盘数据，Mac / Android 改的内容 PC 看到一致，反之亦然 | 跨端互通用例全部通过（12.4） |
| G2 | **视觉与交互对齐 Mac 设计稿**，同时遵循 Windows 使用习惯（快捷键、标题栏、DPI、安装与更新） | 8 个视图逐屏对照设计稿，差异只出现在第 10 章所列项 |
| G3 | **不丢数据、不误覆盖云端**：断网、被限速、网盘列表延迟都不能导致本地旧数据覆盖云端 | 同步三铁律（7.1）+ 故障注入用例 |
| G4 | 富文本编辑**可靠**：粘贴图片、表格、列表这三类最容易出问题的操作有明确容错与反馈 | 12.3 编辑器用例 |

### 1.3 范围

**范围内（In Scope）**

- 百度网盘 OAuth 登录、令牌保存与续期、退出登录。
- 笔记：新建 / 编辑 / 富文本 / 图片 / 表格 / 列表 / 置顶 / 回收站 / 彻底删除；笔记本与标签。
- 「快同步」虚拟笔记（跨设备共享的随手记）与「快任务」（四状态任务 + 备注 + 截止时间）。
- 按篇增量同步、三方合并、冲突副本、墓碑、附件同步、设备会话（手动下线）、头像同步。
- 设置面板（同步状态、云端目录、账号、设备、存储空间、使用说明）。
- Windows 平台适配：安装包、协议注册（`tongnote://`）、DPI、快捷键、窗口状态记忆、日志。

**范围外（Out of Scope）**

| 不做 | 原因 |
|---|---|
| 自建服务器 / 账号体系 / 订阅 | 产品核心承诺是「无服务器、数据归用户」 |
| 多账号切换、第三方账号登录（微信 / Apple / 邮箱） | Mac 版也没有，且网盘授权天然是单账号 |
| 实时协作、评论、分享链接 | 同步模型是「按篇文件 + 轮询」，无推送通道 |
| 深色模式 | Mac 版为固定浅色，三端保持一致；列入 P2 待议（14.3） |
| Markdown 全量导入导出 | 仅保留「旧 Markdown 笔记只读升级」兼容（见 6.5） |
| 正文段落级对齐（左 / 中 / 右） | 不在三端数据契约内，故意不做；**只有表格单元格对齐** |
| 选中文字浮动格式窗 | Mac 版已关闭（`SelectionFormatPanel.isEnabled = false`），PC 不做 |

### 1.4 平台范围

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 21H2 及以上、Windows 11；x64 必须，ARM64 为 P2 |
| 运行时 | WebView2 Runtime（Win11 自带；Win10 由安装包静默安装 Evergreen Bootstrapper） |
| 屏幕 | 100% / 125% / 150% / 200% 缩放均可用；最小窗口 960×620 |
| 网络 | 允许离线使用（读写本地）；联网后自动同步；需能访问 `openapi.baidu.com`、`pan.baidu.com`、`c.pcs.baidu.com` 与百度 dlink 下载域名 |
| 同机多开 | 不支持多实例（第二次启动应把已有窗口置前，见 PC-N-07） |

## 2. 用户与使用场景

### 2.1 目标用户

| 画像 | 诉求 | 对应能力 |
|---|---|---|
| 个人知识工作者（日志、读书、投资复盘） | 随手记、结构化、图文混排、手机电脑都能看 | 富文本、笔记本、标签、表格、跨端同步 |
| 重视数据归属的人 | 不想把笔记交给第三方服务器，能随时迁移 | 数据存自己的网盘，开放格式（受控 HTML + JSON） |
| 日常待办用户 | 手机记、电脑处理，要有备注和截止时间 | 快任务四状态、逾期提醒、备注可带图 |

### 2.2 核心场景

| 编号 | 场景 | 关键路径 |
|---|---|---|
| S1 | 首次使用：登录 → 自动拉取网盘上已有的笔记 | 登录页 → 浏览器授权 → 回调 → 主界面 → 启动全量同步 |
| S2 | 写日志：新建笔记 → 输入 → 粘贴截图 → 插表格 → 自动保存 → 自动上传 | 编辑器 + 本地落盘 + 30 秒节流上传 |
| S3 | 手机上改了，电脑点开就能看到最新 | 点开笔记 → 插队拉取该篇 |
| S4 | 记待办：输入回车创建 → 展开写备注贴图 → 设截止日期 → 完成 | 任务页 + 保存即传单条 |
| S5 | 两台设备同时改了同一篇 | 冲突副本（笔记）/ 字段合并（任务） |
| S6 | 弄丢一台设备 | 设置 → 登录设备 → 下线 |
| S7 | 断网写笔记，回家联网后自动补传 | 本地脏标记 + 间隔全量补传 |

## 3. 总体架构与技术约束

### 3.1 分层（与 Mac 同构）

```
┌──────────────────────────────────────────────────────────────┐
│ UI 层（Avalonia）  登录 · 三栏壳 · 侧栏 · 列表 · 编辑器容器 · 任务 · 设置 │
├──────────────────────────────────────────────────────────────┤
│ 富文本层  WebView2(contenteditable) ⇄ 受控 HTML 编解码（RichTextHtmlCodec）│
├──────────────────────────────────────────────────────────────┤
│ 业务层   NoteStore · TodoStore · NotebookStore · AvatarStore · 会话      │
├──────────────────────────────────────────────────────────────┤
│ 同步层   SyncEngine(SyncScope 队列) · SyncRules(三方合并) · DeviceRegistry │
├──────────────────────────────────────────────────────────────┤
│ 网盘层   BaiduPanClient（OAuth · 列目录 · 分片上传 · dlink/filemetas 下载）│
├──────────────────────────────────────────────────────────────┤
│ 存储层   %LOCALAPPDATA%\tonote\*.json + attachments\  （原子写）          │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 技术选型（沿用现有工程，需求层面的约束）

| 项 | 选择 / 约束 | 理由 |
|---|---|---|
| 语言与框架 | .NET 8 + Avalonia 11；Core 库（`Tonote.Core`）与 UI（`Tonote.App`）分离 | 现有工程已建；Core 可单测、可脱离 UI 跑真实网盘测试 |
| 富文本 | **WebView2 + contenteditable**，正文即受控 HTML；无 WebView2 时退回纯文本框且**不得破坏已有 HTML** | Mac 用 TextKit 自绘表格，Windows 无对应物；DOM 表格是最低成本的等价实现 |
| 持久化 | JSON + 受控 HTML；写入一律「临时文件 + 原子替换」 | 与 Mac `.atomic` 写等价，防断电损坏 |
| 网络 | HttpClient，单请求超时 90 秒，`User-Agent: pan.baidu.com`（取直链与下载必须带） | 百度接口要求 |
| 响应解码 | 按字节 UTF-8 解码，禁止依赖系统代码页 | 避免中文文件名 / 内容乱码（中文 Windows 默认 GBK） |
| 令牌安全 | 令牌文件放用户目录；可选用 DPAPI 加密（P1）；**日志中不得出现 token / secret** | Mac 为 0600 明文文件，Windows 无 chmod 语义，用 DPAPI 补强 |
| 凭证 | `baidupan.secret.json`（`appKey / appSecret / appID`）**不入库**，构建期复制到输出目录 | 与三端一致 |

### 3.3 硬约束（违反即视为缺陷）

1. **数据格式不可单端演进**：不得为 PC 单独新增 `Note / Todo` 的必填字段；新字段必须是可选、带默认值、旧端忽略（沿用 `decodeIfPresent` 语义）。
2. **云端目录与文件命名固定**（见 7.2）。
3. **正文只存相对路径图片**：`attachments/<noteUUID>/<imageUUID>.<ext>`；任何 `file:///`、`blob:`、`data:` 引用都不得写入笔记。
4. **WebView 里的脚本、样式不得被当作正文持久化**（`<script>` 放 `<head>`，保存只取 `body.innerHTML` 并经受控标签集清洗）。
5. **不删云端文件本体**：彻底删除只写墓碑 `purged=true`，不物理删除 `notes/<id>.json`（附件目录在无引用时可删）。

### 5.2 PC-S 云同步（总览；详细规则见第 7 章）

## 6. 数据需求

### 6.1 本地存储（Windows 路径）

根目录 `<TONOTE>` = `%LOCALAPPDATA%\tonote`（环境变量 `TONOTE_DATA_ROOT` 可覆盖，用于测试隔离）。

| 文件 | 结构 | 说明 |
|---|---|---|
| `notes.json` | `[Note]` | 全部笔记（含回收站、墓碑、「快同步」虚拟笔记） |
| `todos.json` | `[Todo]` | 全部任务（含墓碑） |
| `note-sync.json` | `{UUID: SyncCursor}` | 笔记同步基线，**只落本机** |
| `todo-sync.json` | `{UUID: SyncCursor}` | 任务同步基线，**只落本机**（含 `baseTodo` 快照） |
| `device.json` | `{deviceId, sessionId, deviceName}` | 设备身份 |
| `baidupan-token.json` | `{accessToken, refreshToken, expiresIn, scope, createdAt}` | 令牌 |
| `notebooks.json`（本地配置） | 自建笔记本名单、removed 名单、dirty 标志 | Mac 存在 `UserDefaults`，PC 存同名 JSON 或注册表，**语义一致** |
| `settings.json` | `avatar.id`、`lastSyncDate`、窗口状态等 | 同上 |
| `sync-status.json` | `{kind, message, date}` | 同步状态，便于重启后诊断 |
| `attachments\<noteUUID>\<imageUUID>.<ext>` | 二进制 | 图片附件（任务备注图片目录为 `<任务UUID>`） |
| `paste-debug.log` / `table-debug.log` / `sync-debug.log` | 文本 | 诊断日志，单文件上限 2 MB，滚动保留 3 份，**不含令牌与笔记正文** |

**编码**：`JSON` 缩进 + 键排序，日期 ISO-8601（与 Mac `.prettyPrinted + .sortedKeys + .iso8601` 一致，保证 diff 稳定）；UTF-8 无 BOM。  
**写入**：临时文件 + 原子替换；`load` 失败（缺失 / 损坏）时回退空集合，**但损坏文件要先备份为 `*.corrupt-<时间戳>` 再回退**（Mac 无此保护，PC 增强，防止一次解码失败后被空数据覆盖）。  
**不灌入演示数据**：本地为空时不生成示例笔记，登录后直接从网盘拉取（避免把示例当作本地新增推到云端）。

### 6.2 数据模型

**Note**（12 键，全部 `decodeIfPresent` + 默认值）

| 字段 | 类型 | 缺失默认 | 说明 |
|---|---|---|---|
| `id` | UUID | 必填 | 云端文件名即此值 |
| `title` | string | 必填 | — |
| `body` | string | 必填 | 受控 HTML（富文本）或旧 Markdown |
| `createdAt / updatedAt` | ISO-8601 | 必填 | — |
| `deletedAt` | ISO-8601? | nil | 非空 = 在回收站 |
| `tags` | [string] | `[]` | — |
| `notebook` | string | `"工作日志"` | — |
| `pinned` | bool | false | — |

| `rev` | int | 0 | 云端版本号，每次上传自增 |

### 6.3 受控 HTML 协议（编解码必须与三端一致）

**目标**：只允许固定标签与属性集合 → ① 跨端解析一致 ② 正文不出现 `file:///` / `blob:` 临时引用 ③ 图片只以相对路径存放。

| 类别 | 允许标签 | 说明 |
|---|---|---|
| 块 | `p` `h1`–`h6` `blockquote` `pre` `ul` `ol` `li` `table` | `li` 用 `data-level="n"`（n>0 才写，0~7）；连续同类列表项合并为一个 `<ul>/<ol>` |
| 表格 | `table` `tr` `td`（解码也认 `th`、`tbody/thead/tfoot`） | `table` 级 `data-widths` / `data-fullwidth="0"`；`td` 级 `data-align`（左不写）/ `data-bg` |
| 行内 | `strong` `em` `u` `s` `a[href]` `span[style]` `img[src,width,height]` `br` | `span` 的 style 仅 `font-size:Npx` / `color:` / `background-color:` |

**行内 run 的编码嵌套顺序（由内到外，固定）**：`img`（图片短路）→ `a` → `span font-size` → `span color` → `span background-color` → `s` → `u` → `em` → `strong`（最外层）。  
**标题内不再套 `<strong>`**（语义冗余）。块之间以 `\n` 分隔，最后一块无尾随换行，保证「编码 → 解码 → 编码」稳定。  
**数字格式**：整数输出 `24`，非整数 `"%.1f"`。  
**转义**：文本 `& < >`；属性再加 `" '`。解码实体固定 7 项：`&amp; &lt; &gt; &quot; &#39; &apos; &nbsp;`（`&nbsp;` → 普通空格），**无通用数值实体解析**。  
**解码容错（必须实现）**：
1. `<tbody>/<thead>/<tfoot>` 递归展开；`<th>` 当 `<td>`。
2. 块级裸 `<img>`（不在 `<p>` 内）按单图段落解码。
3. 未知标签递归 children，为空则 `rawText` 兜底成段落。
4. 多个 `style` 属性合并（`;` 连接）；其他属性重复取首个。
5. 注释 `<!-- -->` 整段跳过；未闭合标签末尾依次弹栈。
6. `div`、`font`、绝对路径图片等浏览器 `contenteditable` 产物，**写盘前**必须先在 JS 侧规整成受控标签集，再经 `Encode(Decode(html))` 校验，不通过不写盘并报错。

**WebView 保存规则**：脚本放 `<head>`；保存只取 `document.body.innerHTML`；清洗后写盘；内联 `data:` / `blob:` 图片在保存前必须转存为附件相对路径。

### 6.4 表格模型规则

| 项 | 规则 |
|---|---|
| 上限 | 100 行 × 32 列；每列默认固定 100px |
| `columnWeights` | 权重和为 1；`nil` = 等宽；仅当 `count == columnCount` 且全 >0 才保留；增删列后置 nil |
| `fullWidth` | true = 占满编辑区（不写属性）；false = 固定列宽（写 `data-fullwidth="0"`）；新建表默认 false |
| 矩形化 | 行不足补空单元格、超出截断；每个单元格至少一个空段落；过滤嵌套表格并归一化颜色 |
| 增删 | `insertRow` 沿用相邻行的对齐与背景色，`insertColumn` 沿用左邻列；`removeRow` 须 `rowCount>1`，`removeColumn` 须 `columnCount>1` |
| `plainText` | 单元格间 `\t`、行间 `\n` |

### 6.5 旧 Markdown 笔记兼容

`contentFormat` 缺失或为 `markdown` 的笔记：首次在富文本编辑器打开时按 `MarkdownConverter` 渲染（**有损简化**：围栏代码行丢弃、标题仅到 h3、连续普通行合并为一段、仅 `attachments/` 前缀的 `![](…)` 才转图片、其余占位符按纯文本）；**编辑后升级为 `richText` 并写回**；仅打开不编辑不得改动其 `body` 与 `updatedAt`。

## 7. 同步需求

### 7.1 同步三铁律（高于一切功能需求）

1. **下载失败绝不能当成「云端无此文件」**，也不能用「列目录查不到」推断（断网时同样查不到）。
2. **`create` 返回 `errno=0` 即视为已写入**；回读只用于确认，回读失败只重试回读，**不 `rev+1` 重传**。
3. **只有「目录列表里没有该 id 且本篇从未同步过」才能认定云端无文件**，否则跳过或上抛，等下一轮。

### 7.2 云端目录（固定契约）

```
/apps/tong_log/
├─ notes/<UUID>.json          一篇一个：正文、rev、updatedAt、deletedAt、purged …
├─ todos/<UUID>.json          一条任务一个
├─ attachments/<UUID>/<UUID>.<ext>   图片；路径与正文相对路径一致（笔记与任务共用）
├─ notebooks.json             { names, removed }
├─ devices/<deviceId>.json    每台设备一份，用于手动下线
├─ avatar.json                { "id": "tong" }
└─ manifest.json              旧格式，仅首次迁移读取，此后不再写
```

- 列目录：分页 `limit=200`，上限约 5000 条；仅取 `isdir != 1` 且 `.json` 后缀，文件名 stem 能转 `UUID` 的才计入，非 UUID 文件名忽略。
- 远端根目录固定 `/apps/tong_log`；**测试时**可通过 `TONOTE_REMOTE_ROOT` 改为 `/apps/tong_log/__selftest__/…` 隔离子目录，且程序启动时校验必须落在沙箱内。

### 7.3 合并决策表（`SyncRules.afterFetch`）

`dirty` = 本机有未上传修改；`changed = remoteRev != baseRev || baseUpdatedAt == nil || !sameTime(remoteUpdatedAt, baseUpdatedAt)`；`sameTime` 容差 **1 秒**。

| 条件 | 决策 |
|---|---|
| `remote == nil` | `upload(rev)`，`rev = (baseRev==0 ? 1 : baseRev + (dirty?1:0))`，再 `max(rev,1)` |
| 从未同步（`baseRev==0 && baseUpdatedAt==nil`）且本地无 | `useRemote` |
| 从未同步且 `sameTime(remote, local)` | `useRemote`（避免把同一篇拆成冲突副本） |
| 从未同步且两边时间不同 | `dirty ? conflict : useRemote` |
| `!dirty` | `changed ? useRemote : rememberMtime` |
| `dirty && !changed` | `upload(rev: baseRev==0 ? 1 : baseRev+1)` |
| `dirty && changed` | `conflict` |

`remoteWins`（冲突胜负）用 `>=`，**平局云端胜**。`shouldSkipFetch`：`!cursor.dirty && serverMtime == cursor.serverMtime` 时跳过下载。

### 7.4 同步范围与队列（`SyncScope`）

**范围枚举**

| scope | 含义 | 状态文案 |
|---|---|---|
| `.all` | 笔记 + 笔记本 + 任务 | 「笔记 N 篇 · 任务 M 条」 |
| `.notes` | 笔记 + 笔记本 | 「已同步笔记 N 篇」 |
| `.note(id)` | 仅该篇 | 「已同步本篇」 |
| `.dirtyNotes` | 仅上传本机改过的笔记 | 「已上传笔记」 |
| `.todos` | 全部任务 | 「已同步任务」 |
| `.dirtyTodos` | 仅上传本机改过的任务 | 「已上传任务」 |
| `.todo(id)` | 仅该条任务 | 「已上传任务」 |

**请求入口（唯一）** `request(scope, priority)`：

```
正在同步 → enqueue(scope, front: priority); return           // 插队 = 放队首
空闲     → run(scope)；跑完依次清队列

enqueue 规则：队列里已有 .all → 丢弃新请求；新来 .all → 清空其余只留 .all；同范围去重

run(scope)：
  .dirtyNotes / .dirtyTodos / .todo(id) 且没有可传的脏数据 → 直接返回（不改状态、不发请求）
  status = syncing
  token = validToken(); ensureNotKicked()                    // 每轮开头
  按 scope 执行
  status = success(date) / failed(msg)
  捕获 kicked → 清队列并登出；其他错误 → failed，**不退出登录**
```

**范围越小请求越少**：`dirty*` / `.todo(id)` 只对本机改过的条目各发请求（外加一次目录列表），不下载别端未改动的内容。单篇失败用 `firstError` 收集，遍历完所有 id 后统一抛出，**不中断整轮**。

### 7.5 触发时机（页面范围同步）

**原则**：页面右上角的同步按钮**只同步当前页内容**（有变动先拉远端再上传）；点开页面时先拉一次远端并**插队**；全量同步只在启动与间隔进行。

**拉取（远端 → 本地）**

| 触发 | 范围 | 优先级 |
|---|---|---|
| 应用启动 | `.all` | 普通 |
| 间隔（**前台 45 秒**） | `.all` | 普通 |
| 窗口回到前台 | `.all` | 普通 |
| 点开某篇笔记（含「快同步」） | `.note(id)` | **插队** |
| 打开任务页 | `.todos` | **插队** |
| 列表「一键同步」 | `.notes` | **插队** |
| 快同步篇 / 单篇笔记里的「同步」 | `.note(id)` | **插队** |
| 任务页「同步」 | `.todos` | **插队** |
| 设置面板「立即同步」 | `.all` | 普通 |

**上传（本地 → 远端）**

| 对象 | 触发 | 范围 |
|---|---|---|
| 普通笔记 | 改动后**每 30 秒**一次（**节流**：计时中不重置） | `.dirtyNotes` |
| **快同步** | 改动后**每 15 秒**一次（节流）；已有 30 秒计时时，快同步的改动把截止时间**提前**到 15 秒 | `.dirtyNotes` |
| 笔记 / 快同步 | **离开**该笔记（切换笔记、进任务页、关闭窗口、失活、最小化）→ 取消计时立刻传 | `.dirtyNotes` |
| 任务 | 保存 / 状态流转 / 新增 / 删除后**立即** | `.todo(id)` |
| 任务 | 编辑中的备注输入、截止时间步进 | 只标脏，**不上传** |
| 任务 | 离开任务页 / 退到后台 | `.dirtyTodos` |

**其他约束**：
- 同步中按钮**不置灰**（可再点，进队列）。
- 同步回写**不得**再触发「本地数据变更」通知（避免回环）。
- 离线 / 未登录时上传请求直接忽略，恢复后靠间隔全量补传。
- 关闭窗口时：停止轮询，flush 待上传（最多等待 3 秒）。
- 现有 Windows 的 1.5 秒防抖**应被上表取代**（PC-S-11 的实现任务）。

### 7.6 任务字段三方合并（`mergeTodos(base, local, remote)`）

**祖先快照**：`SyncCursor.baseTodo`（只落本机，每次同步回写时更新）。无快照（旧数据 / 重装 / 从未同步）→ 直接 `.unresolved`，退回冲突副本。

| 情况 | 结果 |
|---|---|
| `local == remote` | 用这份 |
| 只有本机变（`remote == base`） | 本机 |
| 只有云端变（`local == base`） | 云端 |
| 两边都变且不同 | 按下表 |

| 字段 | 双改规则 |
|---|---|
| `notes` | **合不了**：两边都改且不相等 → 整条 `.unresolved`（备注是 HTML，不盲拼） |
| `title` | `updatedAt` 较新者；平局云端胜 |
| `status` | 任一方 `terminated` → `terminated`；否则取更靠前：`todo < doing < done` |
| `plannedAt / startedAt / completedAt` | 一边为空取有值的；两边都有且不同取 `updatedAt` 较新者 |
| `order` | `updatedAt` 较新者 |
| `purged` | `local.purged \|\| remote.purged`（墓碑优先，不看 base） |
| `id / createdAt` | 不变 |
| `rev` | `max(local,remote)`；上传前由发布步骤重设为 `max+1` |
| `updatedAt` | `max(local, remote)` |

**典型**：手机改备注 + 电脑改状态 → 合成一条；一边设截止时间 + 一边改标题 → 两项保留；一边完成一边终止 → 终止；任一边删除 → 删除；备注双改 → 仍出「（冲突副本）」。  
**合并成功**：下载合并结果引用的备注图片 → `publishTodo(rev = max+1)` 写回原 `todos/<id>.json`，**不生成副本**。

### 7.7 发布、冲突、墓碑

- **发布 `publish`**：最多 3 次；每轮 `ensureNotKicked` → 设 `rev=nextRev` → 上传附件 + 上传 JSON → **回读校验**（`rev` 相等且 `sameTime(updatedAt)`）→ 成功更新 cursor。3 次失败抛「笔记「X」连续三次没能写上云端」。任务 `publishTodo` 同构，且**先传备注图片再传任务 JSON**。
- **冲突副本**：新 UUID、标题不以「（冲突副本）」结尾则追加、`rev=0`、`purged=false`。`resolveConflict`：云端胜 → 本地另存副本上传（`rev:1`），原 id 收下云端；本地胜 → 云端另存副本，本地以 `max(local.rev, remote.rev)+1` 上传。
- **墓碑**：`purged=true` 只传墓碑 JSON、跳过附件；成功后若无其他未 purged 笔记引用 `attachments/<id>/` 则删云端整个附件目录；不删 note 文件本体。
- **附件提取**：正则 `attachments/[0-9A-Fa-f-]{36}/[0-9A-Fa-f-]{36}\.[A-Za-z0-9]+`，`Set` 去重保序；下载失败返回 false 并置 `cursor.serverMtime = nil`。
- **cursor**：只落本机，**不上传**；换设备 / 重装 `baseRev=0`，靠「从未同步」分支按 `updatedAt` 兜底。

### 7.8 下载 / 上传链路细节

**上传三步**
1. `precreate`（POST `xpan/file?method=precreate`）：`path, size, isdir=0, autoinit=1, block_list(百分号编码的每片 MD5 JSON 数组), rtype=3`；分片 4 MiB；MD5 为**每片**小写 hex；成功判定 `uploadid` 存在且 `errno==0`（`uploadid` 兼容 string/int，`block_list` 兼容 [int]/[string]）。
2. 分片 / 秒传：`return_type==2` → 秒传跳过；否则只传 `blockList` 指定序号，POST `superfile2?method=upload&type=tmpfile&path&uploadid&partseq`，multipart 字段名 `file`、`filename="blob"`，带 UA；HTTP≥300 或 `errno≠0` 抛错附响应体。
3. `create`（POST `xpan/file?method=create`）：`path, size, isdir=0, uploadid, block_list, rtype=3`；非 JSON 响应或 `errno≠0` 抛错。

**下载三级兜底**
1. `xpan method=download&path&threshold=0` → 解析 `dlink`；响应不是 JSON（风控 / 网关 HTML）抛 server 并带原文；命中 `errno 20020` 后本进程置 `downloadByPathBlocked`，后续直走 2。
2. 列父目录拿 `fs_id`（顺手缓存 路径→fs_id；`create` 成功也立即缓存）→ `method=filemetas&fsids=[id]&dlink=1` 取链。
3. 250ms 后强刷父目录重拿 `fs_id` 再取一次。
- 直链 GET 追加 `access_token` + `User-Agent: pan.baidu.com`；取链失败 / 404 / 内容为空均进入 **3 次重试 + 退避**（300ms×attempt），每轮重新取链。**只抛临时错误，绝不抛 `notFound`**。
- `deleteRemote` 把 `errno=-9 / 31066` 视为「已不存在」白名单。
- 回读校验：最多 3 次、退避 400ms×retry。

### 7.9 同步缺口与已知风险（PC 需知晓）

1. 笔记正文无字段合并，冲突仍拆「（冲突副本）」；点开即拉取与 30 秒上传只是缩短冲突窗口。
2. 网盘无推送：别端改动最快在「点开页面」或下一次间隔轮才可见。
3. 多条任务连续保存会各发一次上传（队列只对同一条去重），可能触发网盘限速；PC 首版可接受，P2 优化为合并窗口。
4. 强杀 / 崩溃时最多丢最近 15~30 秒**未上传**的修改（本地已落盘，不丢本地）。
5. 没有显式「待上传」角标；PC 建议在侧栏状态区显示「N 项待上传」（P1，PC-SY-05）。
6. 点开页面的拉取没有取消；快速连续切换多篇会排出多个 `.note(id)`，依次跑完。

## 9. 非功能需求

### 9.1 性能

| 指标 | 目标 |
|---|---|
| 冷启动到可输入 | ≤ 2 秒（本地 1000 篇笔记、无网络） |
| 切换笔记 | ≤ 200ms（含 1 万字 + 大表格） |
| 输入延迟 | 常规笔记 < 50ms；22 列 × 50 行大表格 < 100ms |
| 列表滚动 | 1000 篇笔记 60fps（虚拟化列表） |
| 同步一轮（无变更） | 仅 1~3 个请求（列目录 + 笔记本 + 任务列目录） |
| 内存 | 常驻 < 400 MB（含 WebView2 进程） |

### 9.2 可靠性

- 原子写 + 损坏文件备份（6.1）；崩溃后重启不丢已落盘数据。
- 所有网络调用有超时（90 秒）与分类错误：临时错误（可重试）/ 永久错误（需用户处理）/ 被踢（登出）。
- 同步失败不影响本地读写；离线完全可用。
- 数据迁移：旧版本数据（含 `WorkLog` → `tonote` 目录改名）自动升级，**升级前不覆盖，升级失败可回退**。

### 9.3 安全与隐私

| 项 | 要求 |
|---|---|
| 令牌 | 仅存本机用户目录；P1 用 DPAPI 加密；日志与诊断信息不得含 token / secret / 笔记正文 |
| `client_secret` | Mac 现状为 GET query 传输（已知风险）；PC 改为 POST body（若接口支持），否则维持并在文档标注 |
| 链接 | 仅允许 `http / https / mailto`；`javascript:` 等一律拒绝 |
| WebView | 禁止导航到外部页面（外链交系统浏览器）；禁用开发者工具（发布版）；`file://` 访问仅限 attachments 目录 |
| 数据可见范围 | 只读写 `/apps/tong_log`；页脚文案如实说明 |
| 笔记明文 | 本地 `notes.json` 为明文（与 Mac 同安全等级）；列入 P2「可选本地加密」 |
| 设备下线 | 设备号白名单校验 `^[A-Za-z0-9-]{8,80}$`，防路径注入 |

### 9.4 兼容性

- **跨端数据互通**是第一兼容目标：PC 写出的 JSON / HTML，Mac 与 Android 必须原样可读；反之同理（见 12.4）。
- WebView2 产出的 HTML 与 Android WebView 类似（`tbody`、`div`、`font`），解码容错见 6.3。
- 系统代理、企业网络（需放行域名见 1.4）。

### 9.5 可观测性

- 同步日志（`sync-debug.log`）：每轮 scope、请求数、耗时、失败原因；不含正文。
- 粘贴日志（`paste-debug.log`）：剪贴板实际格式清单与走的分支。
- 表格日志（`table-debug.log`）：增删行列命中、上限、读回失败。
- 设置面板「复制诊断信息」一键导出（PC-SE-07）。

### 9.6 本地化与可访问性

- 界面文案简体中文；日期格式 `M月d日` / `yyyy-MM-dd HH:mm`；数字不带千分位。
- 国际化框架预留（文案集中，见附录 A），首版仅简体中文。
- 可访问性（P1）：所有按钮有可访问名称；对比度满足 WCAG AA；键盘可完成新建、搜索、切换、增删笔记等主流程。

## 10. Mac → PC 差异决策表

| 主题 | Mac 实现 | PC 决策 | 原因 |
|---|---|---|---|
| 富文本内核 | TextKit 1 + `NSTextTable` 自绘 | WebView2 + contenteditable | Windows 无同等原生表格排版；DOM 表格成本最低 |
| 表格边沿手柄 | 自绘灰圆 → hover 蓝加号 + 引导线 | DOM 手柄（P1），首版可由工具栏浮层替代（P0 兜底） | 内核差异 |
| 单元格菜单 | AppKit `NSMenu` | Avalonia / HTML 浮层，菜单项一致 | — |
| 标题栏 | 44px 交通灯标题栏 | 系统标题栏 | 平台习惯，不逐像素复刻 |
| 图标 | SF Symbols | 自绘线性矢量图标 | 版权与一致性 |
| 令牌存储 | 0600 JSON | 用户目录 JSON（P1 DPAPI） | Windows 无 chmod |
| 本地配置 | `UserDefaults` | JSON 配置文件 | 语义等价 |
| 快捷键 | 几乎无 | 补齐 Windows 常用快捷键（5.17） | 用户预期 |
| 回收站内搜索 | 搜索框可见但无效 | **PC 修正：生效** | 修正体验缺陷 |
| 侧栏账号名 | 硬编码「老王的工作台」 | **PC 修正：显示真实昵称** | 修正缺陷 |
| 登录页页脚 | 仍写 worklog 目录 | **PC 修正：写 `/apps/tong_log`** | 修正文案 |
| 字号菜单勾选 | 误把 15 标勾（实际默认 14） | **PC 修正：勾选实际字号** | 修正缺陷 |
| 登录失败文案 | 两条指向不同文件 | **PC 统一指向 `baidupan.secret.json`** | 修正缺陷 |
| `ASWebAuthenticationSession` 路径 state 只发不验 | 不校验 | **PC 全部校验 state** | 安全 |
| 置顶 | 不参与排序键，仅间接置顶 | **保持一致**（刻意不改），避免三端行为分叉 | 三端一致优先 |
| 深色模式 | 无 | 无 | 三端一致 |
| 备注双改冲突 | Mac 另存副本；Android 整条覆盖 | **PC 另存副本**（对齐 Mac） | 不丢数据 |
| 同步范围 | `SyncScope` 队列 | **对齐 Mac / Android** | 三端同步语义统一 |
| 选中文字浮动格式窗 | 已关闭 | 不做 | — |
| `ScalableImageCell` 图片缩放手柄 | 未接入 | 不做；图片固定 480px 上限 | — |
| 附件路径分隔符 | `/` | **一律 `/`**（Windows 路径读写时转换） | 跨端一致 |

### D.2 实机补充（已体现在对应需求中，Windows 需注意）

1. **同步按钮文案会随状态跳变**（见 D.1-6）。同步中按钮变宽，Mac 上会把「最近更新」挤成两行——这是 Mac 的布局瑕疵，**PC 不应复刻**：按钮宽度固定为容纳「一键同步」的宽度，排序项不得换行。
2. **打开任务页 / 展开任务、点击「快同步」卡都会立刻触发一次插队拉取**（`SyncScope` 见 7.4），同步中界面其它部分仍可点击。
3. **设置面板内按 Esc 即关闭**，且无需先聚焦；PC 版必须支持 Esc（PC-X 已列）。
4. **表格边沿的灰圆是常驻的「插入点」，不是 hover 才出现**（悬停才变蓝色加号）。它们**只负责加行 / 加列**；删除行列、单元格背景、匹配笔记宽度、删除表格走**光标所在单元格右上角的 16px 下箭头菜单**（PC-T-08）。**PC-T-07 原写作「顶边 / 左边 hover 出现 ＋」，应改按本条：常驻灰圆 + 悬停变蓝，Windows 版同样常驻显示，否则用户看不出可以点。** 下箭头菜单为系统原生菜单，本次实机截图未能捕获菜单内容，菜单项以 PC-T-08 与附录 A「表格」行为准。
